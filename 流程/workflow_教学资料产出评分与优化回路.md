# 教学资料产出 · 评分与优化回路（2026-10-24 郭老师定）

**一句话**：凡是"给学生用"的产物，出来之后不许直接交差——先由主模型写一份评分细则，再由一个**没参与制作**的评分子 Agent 打 10 分制，**低于 8 分不算数，要返工重做**。

> 原话（2026-10-24 09:15 郭老师）：
> 「加入一个评分与优化机制。每次产出产物之后，主模型需要制定评分标准与细则。
> ① 制定标准：根据学生的学情、年龄特点，以及官方对学生学习的要求与规范，为设计的练习与资料制定评分标准与细则。
> ② 独立评分：在子 Agent 产出产物时，必须由专门的『评分子 Agent』进行评分。为了避免作弊，做事情的 Agent 和评分的 Agent 不能是同一个。
> ③ 优化机制：以满分 10 分为例，8 分算合格。如果子 Agent 的评分未达 8 分，则需要重新制作优化。」
>
> 关联：[[反馈/feedback_教辅产出必须经独立评分]]｜[[参考/reference_教辅评分细则模板库]]

## 一、触发范围

**要触发**（产出物是给学生用的）：练习册、专项训练、讲义、词卡／速查页、单词书、真题卷、答案册／解析册、阅读材料、给学生的插画与学习站点页面。

**不触发**：内部脚本与探针、平台发布文案草稿、给我自己看的中间产物、数据整理与索引。

## 二、三步回路

### 第 1 步 · 主模型定标准（不许外包）
主模型在派制作任务前、或产物回来后，必须先写出一份**评分细则**，六件事写全（缺一件＝细则不合格）：
1. **维度与权重**（10 分制）
2. **判定口径**（可判定的句子；禁止"好一点""丰富一点""排版更佳"这类不可判定的话）
3. **取证方式**（具体到文件路径、脚本名、抽多少页／多少题）
4. **核验状态**（✅已核 / ⭕未核并写明原因）
5. **扣分规则**（每条扣几分、单项上限）
6. **合格线与返工触发**（≥8.0 合格；<8.0 返工）

细则的三条依据必须落到细则里：
- **学生学情**（年级、已学词汇量、已做过的题型）
- **年龄特点**（专注时长、字号下限、图形比重、句子长度）
- **官方要求与规范**（课标能力分级、当地考试说明与真题题型结构）

细则原文**原样传给评分子 Agent**；评分 Agent **不得自行改标准、不得自定权重**。

### 第 2 步 · 独立评分（不同 Agent）
- 评分子 Agent **必须没有参与过该产物的制作**。
- **做事的 Agent ≠ 评分的 Agent ≠ 执行返工的 Agent**（三者互不重叠）。
- 评分 Agent **只读**：不许改产物、不许跑会写盘的脚本、不许与制作 Agent 讨论。
- 评分 Agent **必须给可核的扣分证据**（页码／行号／文件路径／命令输出），不许只给结论。
- 输出：总分（10 分制，1 位小数）＋ 每维得分 ＋ 扣分清单（位置／证据／为什么扣／怎么改）＋ 判定（合格 ≥8.0 / 不合格 <8.0）。

### 第 3 步 · 返工（只有不合格才做）
- <8.0 ⇒ 制作 Agent 按扣分清单返工；返工后**重新评分**。
- 复评的评分 Agent 可以换人，也可以是同一人；但**返工执行者不许自评**。
- 返工上限 **2 轮**；两轮仍 <8.0 ⇒ **停下报给郭老师**（附分数、扣分清单、卡在哪），不许无限自检。
- ≥8.0 ⇒ 静默落盘交付，不主动汇报。

## 三、评分记录（留得下、查得到）

每次评分落两份文件，路径按项目自定（本项目约定 `D:\ds-work5\_qa\`）：

| 文件 | 谁写 | 内容 |
| --- | --- | --- |
| `<产物>-评分细则_vN.md` | 主模型 | 上面六件事写全的细则原文 |
| `<产物>-评分报告_vN.md` | 评分子 Agent | 总分表＋每维扣分条目＋判定＋返工清单 |

**细则必须在评分开始前就落盘**——先有标准、后有分数，否则等于事后找补。

## 四、红线

1. **不许自己评自己**：主模型定的细则、主模型执行的评分 = 作弊。
2. **不许三合一**：同一个 Agent 不能既做产物、又打分、又执行返工。
3. **不许没有细则就打分**。
4. **不许把评分当形式**：扣分必须落到可核证据；给不出证据就标 ⭕未核，不许猜。
5. **不许无限自检**：返工上限 2 轮，之后交人。
