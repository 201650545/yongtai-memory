# Agent 产出物 · 评分与返工回路（通用版 · 2026-10-24 郭老师定）

**一句话**：任何 Agent（含主 Agent 自己）交出产物之前，先有一份可判定的评分细则，再由一个**没参与制作**的评分子 Agent 打 10 分制，**低于 8.0 不算交付，打回重做**。

> 原话（2026-10-24 郭老师，对主会话）：
> 「加入一个优化机制，即增加『子 Agent 产出物评分标准与细则』。在子 Agent 产出之后，由另一个评分子 Agent 根据该标准与细则对其进行打分，并输出评分。如果评分（满分 10 分）低于 8 分，则打回优化……**我觉得你也适合这条规则**……让所有人都执行这种给自己打分并且不断优化的机制。」

## 一、与教辅专用那份的分工（先看这条，别写两份）

| 产物类型 | 走哪份 | 本文件是否适用 |
| --- | --- | --- |
| 教辅／练习册／词卡／真题卷等「给学生用」的产物 | [[流程/workflow_教学资料产出评分与优化回路]]（依据要落到学生学情／年龄特点／官方规范） | ❌ 不适用，别重复 |
| 其余一切产出物：代码、脚本、文档、报告、方案、记忆条目、技能文件、交接单 | **本文件** | ✅ 适用 |

两份共用同一套骨架（10 分制、8.0 合格线、做事与评分分离、返工上限 2 轮）；差别只在**依据**：教辅看学情，通用看需求与可验证性。

## 二、七维评分表（合计 10.0）

| 维度 | 分值 | 满分标准 | 扣分口径 |
| --- | --- | --- | --- |
| A 落盘实证 | 2.0 | 产物路径存在，且附**当轮**跑出的 `Test-Path`／文件大小／哈希／grep 行号 | 只有口头断言 0 分；引用上一轮旧输出 1.0 |
| B 需求对齐 | 2.0 | 只做被要求的那一个动作，范围没有外扩 | 「顺便优化」「交叉校验」「再跑一遍验证」0 分；夹带无关改动 1.0 |
| C 可复现性 | 2.0 | 结论能被第三方用一条命令复现；数字、哈希、行号、路径齐全 | 缺关键数字 1.0；命令不可复现 0 分 |
| D 事实纪律 | 2.0 | 未验证项明确标「未验证」；异常数值原样上报不解释 | 推断写成事实 1.0；自行解释异常值 0 分 |
| E 交付形态 | 1.0 | ≤200 字结论 ＋ 产物路径 ＋ 关键数字 ＋ 末尾收口；正文进文件不回贴 | 超长回贴／缺路径／缺收口，各扣 0.5 |
| F 红线合规 | 0.5 | 未触碰重启类动作、记忆正文、代提他人改动、浏览器抢占前台等 | 任一触碰 → 0 分并触发一票否决 |
| G 自评留痕 | 0.5 | 产出方先给一版自评（分数 ＋ 依据），供评分者对照 | 未自评扣 0.5，不否决 |

## 三、一票否决（不看其余得分，直接判不合格）

1. 目标文件已存在、未问就覆盖。
2. 编造验证输出，或把「没跑」写成「已通过」。
3. 擅自定义他人角色／代提他人未提交改动／把「谁是管理员」写进持久配置或记忆仓。
4. 断言「已修复／已删除／已完成」但无当轮输出。
5. 触碰重启类动作（`Stop-Process` / `taskkill` / 重启脚本 / `schtasks` 触发重启）。

## 四、三步回路

1. **定标准**（产出方）：先落盘一份细则，六件事写全 —— 维度与权重／判定口径（必须可判定，禁「好一点」这类词）／取证方式（具体到路径与命令）／核验状态（✅已核 / ⭕未核并写明原因）／扣分规则／合格线。**细则必须先于评分存在**。
2. **独立评分**（评分子 Agent）：没参与制作、只读、不改产物；给可核扣分证据（文件:行号／命令输出）；输出总分（1 位小数）＋ 每维得分 ＋ 扣分清单 ＋ 判定。
3. **返工**（仅 <8.0）：产出方按扣分清单改，改完**重新评分**；上限 **2 轮**，两轮仍 <8.0 ⇒ 停下报郭老师（附分数、扣分项、卡在哪），**不许自己降标准通过**。

## 五、评分子 Agent 的启动契约（spawn 时逐字给出）

1. 产物路径清单（只读，不给写权限）。
2. 本次需求原文（用于判 B）。
3. 产出方声称的验证输出（供对照，**不许直接采信**，必须自己复跑）。
4. 要求返回：七维得分表 ＋ 总分 ＋ 判定 ＋ 打回项。

## 六、红线

1. **不许自己评自己**：产出方定的细则由产出方打分＝作弊。
2. **不许没有细则就打分**。
3. **不许把评分当形式**：扣分必须落到可核证据；给不出证据标 ⭕未核，不许猜。
4. **不许无限自检**：返工上限 2 轮，之后交人。
5. **不许为通过而降标准**：分数不够就返工，不改合格线、不改权重。

## 七、适用与豁免

- 主 Agent 自己的交付**同样适用**：先自评，再另起评分子 Agent 复核。
- 豁免（不必评分）：一句话确认、纯查询、无产物的口头回答。

1. **先审核、后评分**：产出完成后不许直接进评分，先过内容审核这一关（审核结论落盘 `<产物>-审核_vN.md`，写清核了什么、哪些核不了、结论是什么）。
2. 审核 Agent 核两件事——**准确性**（数据、答案、出处、口径是否经得起逐条核）与**合理性**（方案是否讲得通、是否符合需求与约束、是否适合目标人群）。
3. 审核不过 ⇒ **先修内容**，修完再进评分；审核与评分都过，这道闸才算过。
4. 审核 Agent **必须没有参与制作**，且**不是评分 Agent**。

**四条角色互不重叠（本条最硬的约束）**

- **细则由派活方（主 Agent）写**，不交给执行制作的子 Agent 写——细则一旦由制作方自己定，标准就会被自我认知污染；
- **评分方必须不是产出方**（郭老师原话："打分的是和产出不一样，要记住了。评分的 Agent 和产出的 Agent 不一样"）；同一次产出里"既做又评"＝**评分无效，直接作废重派**；
- 返工执行方不许给自己打分。

## 八、细则六要素（缺一即细则不合格）

> 落位来源：`D:\Work\_inbox\subagent-scoring\合并方案.md` §2.2 C1；条文取自 [[参考/reference_教辅评分细则模板库]] §三 与 [[流程/workflow_教学资料产出评分与优化回路]] §二·第 1 步。本节把 §四 第 1 步「六件事写全」一句展开成**可执行门禁**。

1. **维度名 + 权重**（合计 10.0）
2. **判定口径** —— 必须是可判定的句子。**禁词**："好一点""更美观""丰富一点""排版更佳""质量较高"，以及一切同义的非可判定表述。
3. **取证方式** —— 具体到：文件绝对路径、脚本名与参数、抽多少页／多少题／多少处。
4. **核验状态** —— 每条依据标 ✅已核 或 ⭕未核（写明为什么没核）。
5. **扣分规则** —— 每条扣几分、单项扣分上限。
6. **合格线与返工触发** —— ≥8.0 合格；<8.0 返工；返工上限 **2 轮**。

**门禁**：**六要素缺一件 ⇒ 该细则不合格 ⇒ 不得进入评分**（不许「边评边补标准」）。

## 九、评分记录格式（两份文件，细则必须先于评分落盘）

> 落位来源：合并方案 §2.2 C6。

每次评分落**两份**文件，路径按项目自定：

| 文件 | 谁写 | 内容 |
| --- | --- | --- |
| `<产物>-评分细则_vN.md` | 派活方（主模型） | 第八节六要素写全的细则原文 |
| `<产物>-评分报告_vN.md` | 评分子 Agent | 总分表 ＋ 每维扣分条目 ＋ 判定 ＋ 返工清单 |

**细则必须在评分开始前就落盘** —— 先有标准、后有分数，否则等于事后找补。

**报告正文四段式**：① **总分表**（每维得分／满分／Σ）；② **每维扣分条目**（位置｜证据｜为什么扣｜怎么改）；③ **判定**（合格 ≥8.0／不合格 <8.0）；④ **返工清单**（按「改动量 × 收益」排序，**最多 6 条**）。

## 十、评分质量抽检（对评分器自身的第二道防作弊）

> 落位来源：合并方案 §2.2 C2。

1. **启用条件**：每 **10 次**评审，**至少抽 1 次**做复评。
2. **做法**：同一次评审由**两个评分子 Agent**各自独立打分。
3. **判定**：两评 **差 > 2 分** ⇒ **两条评分同时作废**，该次评审重来。
4. 抽检不计入返工轮次；抽检发现的问题写进本回路的返工清单。

## 十四、通用层锁死口径（10 分制／8.0／2 轮／0.5 步进／红线 vs 不可验）

> 落位来源：合并方案 §2.1 M1、M2、M3。

1. **打回上限 = 2 轮**（M1）：10 分制、合格线 **8.0**、打回上限 **2 轮** 三项**锁死在 L0/L1**；场景层**只读引用、不可自定义**。任何一份文件再写 1 轮或 3 轮，以本条为准。
2. **步进 = 0.5 连续**（M3）：通用层与场景层的**维度得分**一律 0 / 0.5 / 1.0 / 1.5 / 2.0 …，**不得出现 0.1 等非 0.5 增量**。
   - **0/1/2.5 档不收编**（AI视频旧四维正式废止，不作通用层或场景层刻度）。
   - **0.1 粒度降级为「扣分条目写法」**：场景层可写「缺路径 −0.1」这类**条目**，但**维度得分本身**不得出现 0.1 增量。
3. **红线 vs 不可验，拆成两条互不重叠的条款**（M2）：
   - **红线**（触碰真源／越权／泄露凭据／杀 DSH／改 `D:\记忆` 正文）→ **该维 0 分 ＋ 一票否决，不可打折、不可用替代证据抵扣**。
   - **不可验**（非红线，如本机缺语料、工具不可跑）→ 标 **「⭕未核」＋写明原因＋给替代证据**，按「未核不加分」处理：**不默认满分，也不适用 0/1/2.5 替代档**。
   - 两者**不可互相替代**：不可验**不构成**红线；红线**不因**不可验而减免。
