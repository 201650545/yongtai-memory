# 课件必须先写脚本再生成

> 郭老师指令（2026-10-23）：「**记住课件以后要先写脚本**」。

## 铁律

**任何课件（HTML 交互课件 / PPT / 打印学具）必须先写生成脚本，再跑脚本产出成品；禁止直接手写成品文件、禁止用字符串替换方式手改成品。**

## 来由（2026-10-23《葡萄沟》交互课件的真实代价）

做《葡萄沟》交互课件时直接手写/手改了 4 MB 单文件 HTML，成品即源码。后续每改一处——第 10 句补全、角标文案、`var i`→`let i` 修闭包 bug——都只能靠「精确字符串替换 + SHA256 反证 + 反向剥离对比」来证明确实没动别的地方，成本高且危险。若一开始就有生成脚本，同类改动只是改脚本参数重跑。

## 四条理由

1. **可复现**：同一脚本重跑得到同一成品，谁都能验证、出问题能重建。
2. **可参数化**：换课文 / 换字号 / 换页数只改参数，不动成品。
3. **可验证**：脚本自带断言，成品必须过断言才算生成成功。
4. **可回滚**：改坏了重跑旧脚本版本即可，不必依赖 `.bak` 链。

## 落位约定

- 脚本放项目 `scripts\` 或 `.work_*\` 目录。
- 成品与脚本**同步版本号**（成品头部注明由哪个脚本、哪个版本生成）。
- 脚本里写清三段注释：**输入 → 输出路径 → 断言清单**。

## 反例（实际做过的，禁止重犯）

手写 4 MB 单文件 → 用「精确字符串替换」改内容 → 用 SHA256 反证 + 反向剥离对比证明没动别的。

## 适用范围

- **适用**：HTML 交互课件、PPTX、DOCX 学具、PDF 打印件、数据看板页。
- **不适用**：一次性小文本修改（如改一句话、改个文件名）。
