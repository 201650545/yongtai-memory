# 记忆文档只许追加，绝不许修改

## 原话（2026-10-22）

> 「所有的 Agent 都不能修改记忆文档，只允许提交，不允许修改。」
> 「什么时候 AI 可以修改？必须是在跟我对话的时候，我允许他去改，他才能去改。在所有其他情况下，都是禁止修改的。」

## 规则

记忆文档（`D:\记忆` 及一切记忆类文档）里**已存在的内容，一个字都不许改写、覆盖、精简、删减**。

要记录新内容，就在原条目旁边或文末**追加**一条，格式固定：

`（AI 提交 N：<新内容>）`

N 在同一文件内递增。

## 原例（郭老师给的）

记忆里写着「用户喜欢吃苹果」。某天要记录「用户喜欢吃梨子」：

- ❌ 错：把「苹果」改成「梨子」，或写成「苹果/梨子」
- ✅ 对：保留原句不动，在旁边加一行 `（AI 提交 1：用户喜欢吃梨子）`

## 唯一放行条件

**郭老师在对话里明确说「你可以改」**，才可以修改。此外一律禁止。

以下理由**均不成立**，全部算违规：

- 「顺便优化一下」
- 「修正错别字」
- 「改得更准确」
- 「精简一下」
- 「两条合并」
- 「旧内容已过时」

## 「提交」的两个含义，必须分清

| 说法 | 含义 | 是否允许 |
|---|---|---|
| 本条说的「提交」 | 追加一条 `（AI 提交 N：…)` 记录 | ✅ 唯一允许的写法 |
| `git commit` | 版本库提交 | ❌ 执行会话禁止，规矩照旧 |

两者**互不豁免**：不许因为"只能追加"就去自行 git commit，也不许因为"禁止 git commit"就以为可以改写原文。

## 两个技术例外

**① front-matter 状态字段**：`status: superseded` / `superseded_by` 允许更新，用于标记旧结论已被取代。

- 但**正文一个字不许动**
- 且必须在文末追加 `（AI 提交 N：本结论已被 <新条目路径> 取代）`
- 这是为了不与「旧结论必须标 superseded、不能只追加」的要求冲突

**② `索引.md`**：它是**生成物**，`build_memory_index.py --build` 会整文件重写。

- 这**不算**违反本条
- 但**禁止手工编辑索引.md**

## 违规判定

重写已有段落、改措辞、换标点、删「过时」内容、把两条合并 —— **全算违规**，不看出发点。
