# 浏览器操作必须静默，绝不抢用户正在用的画面

> 🔴 **最高优先级**。这条同时写在 `C:\Users\郭永涛\AGENTS.md` 第 **12** 条（所有 Agent 的第一个读文件），本条目是它的记忆库真源。

## 郭老师原话（2026-10-22，逐字）

> 「只要跟 opencli 有关的操作，全部都要用它的原生操作，不准截图，必须要读取页面信息。反正涉及浏览器的操作、打开跳转、打开其他页面的操作，都不准让它抢占我现在在用的这个画面，必须去静默操作，不然我要把你扇飞。我已经把这句话发给每一个 Agent 了。」

> 「打开 DeepSeek 去搞，要静默操作，不要抢我的浏览器啊。且记住一定要打开新标签页，不要抢别的新标签，自己的标签用完了就打开新的标签页。ChatGPT 镜像版也是同样的原理。」

## 适用范围（无例外）

**一切**涉及浏览器的动作：opencli、kimi-webbridge、任何 CDP / 自动化、任何"帮我在网页上做点什么"。

**明确点名在内**：DeepSeek 官网、ChatGPT 镜像版、豆包、元宝、Gemini 网页版、即梦、千问。

## 四条硬要求

| # | 要求 | 说明 |
|---|---|---|
| ① | **只用 opencli 原生命令** | `tab new` / `open` / `click` / `fill` / `keys` / `tab close`。`eval` **只允许只读**（读 DOM、读状态），**禁止**用 eval 去点击/输入/导航。 |
| ② | **禁止截图** | 一律用 `state` / `find` / `eval` 读页面元素与文本。（他原话：「必须要读取页面信息」） |
| ③ | **绝不抢占他正在看的那一屏** | 不许把窗口切到前台、不许 `ShowWindow` / `SetForegroundWindow` / 抢焦点、不许导航他正在用的标签。开标签必须带 `--window background`。 |
| ④ | **一律新开自己的标签，用完即关** | 从空标签开始；**绝不复用、绝不激活、绝不接管**任何已存在的标签（**含他自己的**）。**自己的标签用完了立刻关掉**；要下一个就再开新的。一轮最多 1 个，需要第 2 个＝走错了，停下报告。 |

## 交付必须自报

> `标签：开了 N / 关了 N / 剩 N`，**N 必须为 0**

**不报或不为 0 ＝ 交付不合格。** 这条没有商量余地。

## 已知未解（必须提前告知，不许闷着）

opencli **2.0.2** 的 `tab new --window background` 在 **Chrome 窗口最小化 / 不在前台**时，**仍可能把窗口唤醒到前面**。参数层无第二开关——`--window foreground|background` 是唯一与窗口模式相关的选项，没有 `--quiet` / `--hidden` / `--no-focus`。

⇒ **跑网页自动化前，先说一句"这一趟可能会弹一下浏览器"**，或改在他不看电脑时跑。**不许假装能做到完全静默。**

## 为什么这条被定成"扇飞级"

2026-10-22 这一晚，多个 Agent（含本会话）反复犯同一个错：
- 新开标签后**弹窗挡住他正在看的页面**
- 有的流程直接 **`ShowWindow` + `SetForegroundWindow`** 把浏览器拉到最前
- 他被挡了几次之后说「真的很心烦」

**病根不在能力，在没人把"静默"当成硬要求写下来。** 这条就是补这个洞。

## 五、怎么连对浏览器：接管他开着的那个，绝不新开实例（2026-10-22 血泪补充）

郭老师原话：「说了要用我已经打开的 Chrome 浏览器，不要去打开新的浏览器。我这个状态栏中不是已经打开了两个浏览器，而且连接了，我的设备、浏览器中都安装好了 OpenClaw，连接码都连接好了，怎么哪个傻逼一直在打开新的无头浏览器？还有快点停掉你那些子线程的，一直打开浏览器，一直都是抢调我的页面打开……我都要被气死了。」

### 5.1 唯一正确通路：opencli Browser Bridge

- opencli 通过**浏览器扩展**连他**日常在用**的 Chrome。`daemon` 跑在 **19825** 端口，`opencli profile list` 里 `connected: true` 的那个 contextId 就是当前连着的（2026-10-22 实测为 `bndfmcmw`；代号会变，**每次现取，不许写死**）。
- **`opencli doctor`** 可诊断连通性。
- **不是** `chrome-devtools-mcp`。那玩意只能控制它自己用 `--remote-debugging-pipe` 拉起的隔离实例，**物理上无法附加到已在运行的 Chrome**（见 [[反馈/feedback_browser_session]]）。

### 5.2 禁止事项（每一条都真实犯过）

| 禁止 | 为什么 |
|---|---|
| ❌ 新开无头浏览器 / 全新 Chrome 实例 / 新 profile | 那是另一个浏览器，不带他的登录态，还占资源。他说过"跟人才一样"就是在骂这个 |
| ❌ 用 `chrome-devtools-mcp` 当默认浏览器工具 | 物理上附加不到他的 Chrome |
| ❌ 反复 `tab new` 开新标签 | 每开一个就在他眼前多一个标签页 |
| ❌ 把窗口切前台、`ShowWindow`、`SetForegroundWindow` | 直接挡住他正在看的页面 |

### 5.3 会话隔离这件事必须讲清

opencli 的 `--session <名>` 是**它自己的逻辑会话**，不等于他 Chrome 里的窗口。技能默认用的 `SESSION='dsc'` 只是 opencli 内部的工作会话名。

**关键**：在该会话里 `tab new` 仍然会在他那个 Chrome 里**真的新建一个标签**。所以「开新标签」这件事本身必须被约束到最低——一轮最多 1 个，用完立刻 `tab close`，绝不长期挂着。

### 5.4 开工前的三步自检（不做就别开工）

1. `opencli profile list` → 确认有 `connected: true` 的 profile，记下 contextId
2. `opencli doctor` → 确认 daemon 活着、扩展版本正常
3. `opencli browser --session <名> tab list` → **只列不碰**，看清他当前开着哪些标签（用来避免抢）

**如果第 1 步没有 connected 的 profile** ⇒ 说明扩展没连上，**如实报告他"我现在连不到你的 Chrome，需要你确认扩展状态"**，**不许自己新开一个浏览器糊过去**。

### 5.5 子 Agent 特别条款

**子 Agent 默认不给浏览器权限。** 理由：子 Agent 不读本文件、不读 SKILL.md，只按主 Agent 的 prompt 执行；主 Agent 忘记叮嘱，它就照旧抢页面（2026-10-22 一晚发生多次）。

- 必须让子 Agent 碰浏览器时，主 Agent 的 prompt 里**逐字附带**四条规定与自报标签行的要求（见本文件"四条硬要求"与"交付必须自报"两节）。
- 事后主 Agent **必须核验**一次 `tab list`，确认没有遗留标签。
- **能不让子 Agent 碰就绝不让它碰**——这是唯一物理有效的防线。
