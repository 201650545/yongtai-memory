# 成品要 HTML 看，且汇总成一个页面

郭老师原话（2026-10-21）：

> 「我在哪里查看呢？我一直跟你说的是我要用 HTML 查看，做好了直接用 HTML 在浏览器打开。
> 你最好是所有的成品都做到一个页面中，这样我就能一次性全部预览了，对不对？这种效率是最高最快的。」

## 执行标准

1. **交付物默认给 HTML**，不是只给 PDF/PNG；做好就用浏览器打开给他看。
2. **所有成品汇总到同一个 HTML 预览页**（一个页面 = 一张总览），
   页内分区：交付清单表 → 每本册子逐页预览 → 小红书草稿预览（首图＋标题＋正文全文＋话题＋附件）。
3. 页面要**自足可读**：目录/导航、规格、状态、文件链接都在页内，
   他不用去翻文件夹、不用猜哪个文件是最新的。
4. 生成器要可重跑（成品改了就重跑一次总览），别手工拼页面。

## 本项目的落地

- 总览页：`D:\Work\English-Content-Factory\02_Projects\HN-ENGLISH-666\03_Products\00_总览预览\★总览_全部成品_v1_261021.html`
- 生成器：`06_templates\_build_overview.py`（改完成品重跑它即可）
- 自查脚本：`06_templates\_check_overview.py`（查坏图/断链，出截图）
- ⚠️ 坑：PDF **不能当 `<img>`** 渲染 ⇒ 用「PDF 下载卡片」代替（否则总览页会出现裂图）。

## 顺带记住的偏好

- 他要**一次看全**，不是"我给你三个链接你自己挑"。
- 预览页比交付文件本身更重要：交付文件是产物，预览页是**汇报**。
