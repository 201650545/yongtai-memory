# 成品要 HTML 看，且汇总成一个页面

郭老师原话（2026-10-21）：

> 「我在哪里查看呢？我一直跟你说的是我要用 HTML 查看，做好了直接用 HTML 在浏览器打开。
> 你最好是所有的成品都做到一个页面中，这样我就能一次性全部预览了，对不对？这种效率是最高最快的。」

## 执行标准

1. **交付物默认给 HTML**，不是只给 PDF/PNG；做好就用浏览器打开给他看。
2. **所有成品汇总到同一个 HTML 预览页**（一个页面 = 一张总览），
   页内分区：交付清单表 → 每本册子逐页预览 → 小红书草稿预览（首图＋标题＋正文全文＋话题＋附件）。
3. 页面要**自足可读**：目录/导航、规格、状态、文件链接都在页内，
   他不用去翻文件夹、不用猜哪个文件是最新的。
4. 生成器要可重跑（成品改了就重跑一次总览），别手工拼页面。

## 本项目的落地

- 总览页：`D:\Work\English-Content-Factory\02_Projects\HN-ENGLISH-666\03_Products\00_总览预览\★总览_全部成品_v1_261021.html`
- 生成器：`06_templates\_build_overview.py`（改完成品重跑它即可）
- 自查脚本：`06_templates\_check_overview.py`（查坏图/断链，出截图）
- ⚠️ 坑：PDF **不能当 `<img>`** 渲染 ⇒ 用「PDF 下载卡片」代替（否则总览页会出现裂图）。

## 顺带记住的偏好

- 他要**一次看全**，不是"我给你三个链接你自己挑"。
- 预览页比交付文件本身更重要：交付文件是产物，预览页是**汇报**。

# 两条交付规则：一律 HTML 单页展示 / 设计必须先出方案和样张

日期：2026-10-21
来源：用户原话——「只要跟图片、PDF、文档有关的内容，通通都做成 HTML，集中展示给我看。」「凡是跟设计有关的，统统都要先做方案，并做出一些案例给我看。做出方案，做出案例，给我来挑选。」

## 规则一：交付物集中成一个 HTML 页
1. 只要产出物跟图片、PDF、文档有关，最终交付都要收敛成一个 HTML 总览页，一页看完，不要丢一堆散文件让用户自己翻目录。
2. 总览页要求：分区清晰、图片有缩略、链接可点、坏图 0、死链 0；原件仍然保留，但入口只有一个。
3. 已有的同类页（封面速看页、风格对比页、旧索引页）改成跳转页，主入口顶到最上面，不允许出现「只看一个页面」却被要求先找入口的情况。

## 规则二：设计类工作先方案、再样张、后挑选
1. 凡是涉及视觉/版式/风格的设计（封面、排版、配色、卡片样式、UI），不许直接开做，也不许只交一版。
2. 先出方案：说明有哪几个方向、各自适合什么、代价是什么。
3. 再出案例：每个方向至少做一张可看的样张（真图，不是文字描述），摆在一起让用户挑。
4. 用户挑定之后才做全量，做完全量再核一次整体一致性。

## 为什么
用户是需求方和验收方，不是执行者。散落文件他要自己找，只有一版设计他没有选择权。把方案和样张摆出来，用户只需要看一眼、指一个方向。
