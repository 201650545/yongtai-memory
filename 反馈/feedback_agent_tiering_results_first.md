# 做事规则：高配规划、低配执行、先成果后合规（2026-10-10 郭老师定，两条一起记）

## 规则一：Agent 高低配分工，直接开干
- **高智力 Agent 只做规划**（写方案/施工图/验收标准），**低消耗 Agent 做执行**（写代码/跑构建/装机）。
- 分配好后**直接开干**，不要来回确认、不要层层请示、不要把"要不要授权"当开场白。

## 规则二：先成果体验，后谈合规
- **做事的目标 = 做出可体验的产品、拿出成果**——不是一直在做逻辑、理关系、缝缝补补、跑一堆没用的东西。
- **拿出成果 → 先让郭老师体验 → 之后才谈合规/合法/安全问题**。合规不是不要，是**放在成果之后**，不许拿它当拖延或挡箭牌。

## 何时要授权：三条硬红线以外默认放行
只有下面三种情况才需要先问郭老师；**其余一律先做**：
1. **不可逆/破坏性**：删数据、重置、改 applicationId/包名、删仓、覆盖安装丢数据；
2. **真实风险**：密钥外泄、真扣费、对外发布、把用户数据传出去；
3. **动到运行中的共享系统**：改正在服务的网关/真机上在跑的状态机的核心时序。

加依赖、加权限、改文档、写代码、跑构建、装机——**都不是"干坏事"，直接做**。

## How to apply
- 接到"做出成果"类任务：规划 Agent 一次把方案写清，执行 Agent 直接干到能装机，中间**不汇报过程、不跑无关验证、不缝补**。
- 先给用户能点、能看、能跑的东西；体验之后再回头补合规。
- 汇报只给结果（装了没有、能不能用、截图），不堆砌过程。
