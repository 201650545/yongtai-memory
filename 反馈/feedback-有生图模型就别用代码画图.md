# 有生图模型，就别用代码画图

> 郭老师原话（2026-10-22）：「那些傻了吧唧的 Agent 总是不知道我有生图模型……我的 API 转发网关还有 Buddy 中都有生图模型可以调用……以后他们还可以调用 ChatGPT 镜像版的 skill 去做图片生成，生成图片的渠道简直多得多了。除此之外，还可以白嫖豆包、元宝等各种能生成图片的网站。」
> 「1. 不要让它们生成水印，水印要裁掉。2. 非必要不要用代码去画图，代码画得真的丑死了，能力又差。除非用代码画又快又适合，才可以选用代码。这条记忆记好」

## 病根：不是没有能力，是没想起来

他的生图渠道**非常多**，但 Agent 不知道 ⇒ 一遇到"要一张图"就退回到手写 SVG / PIL / canvas 画矢量图，产出丑、返工多。
这不是能力问题，是**召回问题**：能力存在但不会被想起（参见 `C:\Users\郭永涛\AGENTS.md` 第 11 条"搜得到 ≠ 想得起来"）。

**实测代价**：2026-10-21 湖南中考英语 688 词封面，先手搓 SVG 扁平矢量被打回一次，改走 `image-gen` 真水彩后又因"封面跟正文没统一"被打回一次。若一开始就按本规则用生图，可省两轮返工。

## 一、渠道清单（要生图先看这里，别自己画）

| 渠道 | 入口 | 适用 | 备注 |
|---|---|---|---|
| **API 转发网关** | `:3100`，模型名 `image-gen`（或 `image` / 中文别名 `猪吧image`） | **主力**，API 直连、不开浏览器、不触发风控 | 内部是回落链：AGNES → 商汤 → 即梦 → 网页版伪 API。详见 [[参考/reference_生图渠道盘点与网页版伪API_20261020]] |
| **AGNES** | `image-gen` 链内 `agnes-image-2.5-flash` | **首选**（无水印、质量好） | 需走 7890 代理；实测 9~10s |
| **商汤日日新** | `sensenova-u1.5-fast` | 免费、快（11~12s） | ⚠️ **带「日日新 sensenova」水印**，必须后处理 |
| **Cloudflare flux** | `@cf/black-forest-labs/flux-1-schnell` | 免费层，实测 6.3s | 接口形状特殊，返回 `{result:{image:base64}}` 无 data 数组 |
| **Buddy（`:8787`）** | — | ❌ **不能生图** | 已三重验证：无生图端点、目录 0 个生图模型、上游全 404。别往这里找 |
| **ChatGPT 镜像版 skill** | `gpt-mirror-extended-review` | 生图质量高、能渲染中文 | **很慢但能出**（3~8 分钟），走「Download this image」下载。见 [[反馈/feedback_mirror_image_gen_slow_works]] |
| **豆包网页版** | opencli 模拟操作 → 伪 API | 白嫖、免费 | 实测出图成功；慢，且反复调会触发风控 |
| **元宝网页版** | 同豆包流程 | 白嫖、免费 | 未单独验证 |
| **即梦** | 网页版 / `jimeng-free-api` | 免费积分，可出高清 | — |
| **千问 / Gemini / Grok / ChatGPT web** | opencli 原生 image 命令 | 免费但要登录态 | 未逐个验证 |

**一句话选择顺序**：要快且无水印 → AGNES（走 `:3100` 的 `image-gen`）；要中文文字准确 → ChatGPT 镜像 skill；要纯白嫖且能忍慢 → 豆包/元宝网页版；**完全不要考虑手写代码画图**。

## 二、水印：一律不要，有就处理掉

- **选渠道时先避开水印源**：商汤带 logo，AGNES 实测无水印 ⇒ 优先 AGNES。
- **避不开就后处理**：商汤水印在右下角、浅灰（亮度 ≥170），图标笔画是深炭（亮度 ~30）⇒ 对水印区做亮度阈值刷白即可，笔画毫发无伤。
- ⚠️ **图标类不要裁切**：裁了会破坏居中对齐（`lesson_ai_icon_to_vector` 已记）。
- 其他场景（海报/插图/封面）水印可以直接裁掉，或按区域刷白。

## 三、代码画图：非必要不用

**这是本条最硬的一条。**

- **默认禁止**：要求"给我一张图/配图/封面/插图/图标"时，**先去上面第一节找生图渠道**，不要抬手写 SVG / PIL / matplotlib / canvas。
- **理由（他的原话）**：「代码画得真的丑死了，能力又差」。手搓矢量图做不出质感、光影、材质，做复杂插画更是不可能。
- **唯一例外**：**又快又适合**的情形才可以用代码。判定标准：
  1. 内容本身就是**结构化/精确**的（图表、流程图、表格、坐标图、几何示意、数据可视化）——这类用代码反而更准更可控；
  2. 或需要**批量、参数化、可重复生成**（比如按数据自动出几十张同版式卡片）；
  3. 或**只需要极简几何**（纯色块、线条、箭头、简单框架图）。
- **判定不清时**：默认走生图。宁可慢一点，也不要交一张丑图。
- **参照已有规范**：[[参考/reference_presentation_system_spec]] —— "AI 负责视觉，HTML/PPT 负责信息"；AI 生图**不承担**正文、长标题、精确数字、表格、数据图、页码；这些必须由 HTML/代码渲染。

## 四、怎么发现 Agent 又忘了

- 若某个 Agent 在该出图的场合开始写 `<svg>` / `ImageDraw` / `matplotlib` ⇒ 违反了本条，停下来改走生图。
- 若生成的图带水印 ⇒ 违反第二条。
- 若 Agent 说"我没有生图能力" ⇒ 它没查这张表，属于召回失败，不是能力缺失。
