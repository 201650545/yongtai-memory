# 记忆写入权限全面放开（2026-10-29 定稿，覆盖此前全部只读口径）

> 郭老师 2026-10-29 原话：「取消我之前那个机制：所有执行 work 项目的 Agent 都可以直接提交和修改记忆，不再需要用户规定谁可以提交、谁只能拥有读的权限。」

## 一、被取消的东西

| 旧口径 | 设立时间 | 状态 |
|---|---|---|
| 记忆文档只许追加、不许修改 | 2026-10-22 早 | **作废** |
| 默认全只读，连追加也要当场点头 | 2026-10-22 晚 | **作废** |
| 获准后也只写变更层，正文永远只读 | 2026-10-22 晚 | **作废** |
| 谁负责写入/提交由用户当场指定 | 2026-10-22 晚 | **作废** |

## 二、现行规则（照这四条执行）

1. **任何 Agent 都可以直接写。** 所有执行 Work 项目的 Agent 可直接提交、修改 `D:\记忆` 内的条目，**无需事先申请、无需被指派身份**。
2. **正文可以直接改。** 可以改写、覆盖、精简、合并、删除过时内容；不必再走"旁边打括号追加"那套。
3. **不再强制变更层。** `_变更提案\` 与 `_inbox\` 降级为**可选**：想留审计轨迹、想留草稿、想给别人接力时才用，不是唯一通道。
4. **遇到旧条目自带的只读声明，以本条为准。** 旧条目正文里的"只读/只许追加"字样不再有约束力。

## 三、仍然保留的技术底线（不是权限，是防坏）

- **`索引.md` 是生成物，禁手改**：改完条目跑 `cd D:\Work\元智能\runners; python build_memory_index.py --build`；体检用 `--check`；`--migrate` 会原地改原文，别乱跑。02:00 的 `EmbedBackfill` 也会自动重建。
- **frontmatter 契约**：每条记忆必须有 `name + description + type + updated`；`type` 走固定词表（project/workflow/lesson/feedback/user/reference/rule/entry/memory/broadcast/explainer/routing）。
- **单写真源**：同一事实只在一处写，别处放指针，避免两份互相打脸。
- **不入库的东西**：密钥、个人信息、过程流水、抓取素材——这些一开始就不进 git。
- **git 入库走单写者脚本** `D:\小浣熊\mm-code\bin\obsidian-commit.ps1`（独占锁 + 显式路径）：让多个 Agent 并发写内容没问题，但并发 `git commit` 会抢锁踩坏仓库，所以提交这一步仍串行。
