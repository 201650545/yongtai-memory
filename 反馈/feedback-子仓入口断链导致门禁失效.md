# 子仓入口断链：README 不是门禁（2026-11-18）

## 事实

对 `D:\Work` 下 19 个活跃子仓做入口体检，结果：

- **17 个的 `AGENTS.md`/`README.md` 完全不提「开工卡」**，0 个提「能力总账」（除库根 `D:\Work\AGENTS.md` 自己）。
- 5 个仓连 `AGENTS.md` 都没有（小程序、启迪、中转站比价、标签链接整理器、文明-游戏）；其中 4 个连 README 都没有。
- `D:\Work\小程序` 顶层空白，三个子工程里只有「跃己」写了记忆落点，`剧本杀` 的 26 KB README 全是业务、0 处提记忆。

## 机制

门禁链写在库根 `D:\Work\AGENTS.md`（开工卡 → 全局变更广播 → 通用规范 → 能力总账 → 项目 AGENTS），
**只在 cwd = `D:\Work` 时被读到**。Agent 把项目文件夹拖进 GUI 当工作目录（很常见），这条链整条跳过：
开工卡没读、负向硬约束（第 10 条禁压测、第 6 条浏览器纪律、3.6 不覆盖已有文件）全部失效。

→ 结论：**子仓 README 的目标读者是人，不是 Agent；它回答"这是什么"，不回答"动手前先读什么"。**

## 做法（已落地，可复用）

1. 每个子仓顶层一份 **15–20 行纯指针 `AGENTS.md`**：① 一句话定位＋产物落点 ② 本项目特有红线（只写例外，不抄通用条款）③ 怎么改本文件 ④ 门禁块（开工卡 → `D:\Work\AGENTS.md` → 本项目 README）。
2. 已有 `AGENTS.md` 的仓**不覆盖**：在 H1 后插 5 行门禁块，原文一字不动，写盘前留 `*.bak-pointer-<时间戳>`。
3. 零入口仓补人读 `README.md`（按真实目录写，不写空壳目录树）。
4. 体检脚本 `元智能\10_AI自成长引擎\scripts\check_work_agents_pointers.py`（只读，三条判据：有 AGENTS.md / 含"开工卡" / 有人读入口），**追加进 08:35 巡检末尾**，失败不影响巡检本体退出码。
5. 批量补入口的生成脚本思路：按仓名映射"定位＋产物落点"，模板化生成；**幂等**（已含"开工卡"就跳过）。

## 踩到的坑

- 生成脚本写盘前必须备份：这批文件在 Git 之外，覆盖就是永久丢失（与 AGENTS 3.6 同源教训）。
- 一次性脚本漏 `import sys` 就崩在 `--dry` 分支——先跑 dry-run，别直接落盘。
- 判定口径若只认字面「开工卡」，将来改写成「开工门禁卡」会误报；要么统一用词，要么改正则容错。
