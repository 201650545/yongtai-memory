## 二、执行含义（这条最要紧）

**默认路径扩展**：从「派 Agent 读代码」→ 扩展为「**派 Agent ＋ 送网页版强模型**」两条并行。
注意用户第二段原话的措辞：「**除了我们直接拉 Agent 去做事情之外**，还可以利用 skill 去问这些网页版」——是**并用**，不是二选一。

### 判据表（按**动作类型**分，不按东西类型分）

| 要干什么 | 走哪条通道 | 关键限制 / 正确落法 |
| :--- | :--- | :--- |
| 读「一个大仓库 / 大段代码结构」 | **优先 DeepSeek 网页版** | 能读公开仓、实测能读 GitHub raw；给 raw URL 别贴几千行（见 §三·a）。本地私有仓它读不到 ⇒ 走 §二·喂料包 或 §四·退路 |
| 出方案 / 出评审 / 长文对比 | **DeepSeek 网页版与 ChatGPT 镜像站都可以** | 镜像站偏**评审**与**出图**；两条通道**必须串行**，一次只绑一个标签（见 §三·附注） |
| 直接产出**可粘贴的代码或内容** | 同上（DeepSeek 网页版 / ChatGPT 镜像站） | 产出后**本地编译 / 跑测试 / 装机才算验收**（见 §四） |
| **跑数据** | 网页版**不能真跑** | 正确落法：让它**出脚本**或**给结论**，**本地执行后回报**；不要把「网页版给了个数字」当跑过了 |

### 三个容易被做错的点

1. **「让它们直接根据我们的代码结构去跑代码」= 编排语，不是执行位置。** 网页版拿不到 `D:\Work` / `D:\listenloop` 的本地磁盘（`feedback-网页版可外包执行` §三 已写明这点：「它们绝大多数项目在 D:\Work，网页版访问不到」）。落地形态是「**它产出 → 本地跑 → 本地验**」，不是「它在云端替我们跑完了」。
2. **「让别人直接拿回来」= 复制回来即用。** 用户明说「然后直接复制回来用」⇒ 产出物要**格式上可直接粘贴**（这一点与 §三·c「只要改动块」是同一件事的两面）。
3. **「跑数据」不能默认交给网页版。** 用户原话说「跑代码、跑数据」，但网页版**没有我们的数据、也不能真跑**；落法必须是它出脚本/结论、本地执行后回报（见 §二·判据表第 4 行）。

## 三、提示词四条硬规矩

> **出处：2026-10-21「读页改造」实战提炼。** 不是 2026-10-22 这次新加的规矩，是那次实战里被强模型**逼出来**的写法沉淀——用户这次说「但是，你的提示词要写好」，指的就是这一套。

**a. 给 raw URL 让它自己读，不要把几千行贴进对话。**
理由：省上下文、不掉行。贴几千行进去，模型的注意力被稀释、答案容易漏掉中段；给 raw URL 让它自己拉，拿到的是完整原文。
配套事实：材料走公开仓 raw URL 是 DeepSeek 官网的**已实测有效**做法（见 `参考/reference-deepseek-web-送审实战沉淀-20261021.md` §一：「材料太长 ⇒ 发到公开仓、只给 raw URL：DeepSeek 能读公网 URL（不依赖 Search 开关）」）。
注意坑：**大文件超 GitHub 展示上限**，只发仓库主页模型会说「读不到」，**必须指向具体 .md 分节文件**（见 §八·2）。

**b. 设计约束要写成「硬约束 ＋ 为什么」。**
不写理由，模型会「顺手」加一档。
实例（来自 2026-10-21 读页改造实测）：**汉字一律 100% 墨色**——因为真机实测对比度只有 **2.76:1**，再降一档就读不清了。写成「汉字颜色必须 100% 墨色，不要加灰阶」它可能自作主张加一档灰；写成「汉字一律 100% 墨色，因为真机实测对比度只有 2.76:1，再浅就读不清」，它就不会动。

**c. 只要改动块，不要整份文件。**
输出格式固定为：**「文件 | 所在方法 + 一行原样锚点 → 替换成什么」**。
理由：网页版回答长了会被截断（已实测：长文稿停在表格或句子中间，DOM 长度连续多轮不变，见 `流程/workflow_ai_wendabao_open.md` 的截断特征记录）。要整份文件就是主动制造截断风险。

**d. 把反直觉的坑写死。**
模型不知道我们踩过什么坑，不写死它就会给出「教科书上对、我们这儿错」的答案。
实例（来自 2026-10-21 读页改造）：**波浪线装饰层必须所有格子占位、无线处画透明**，否则行高不一致、全文跳动。
判据：一句话——**凡是我们「试过才知道」的地方，都要写进提示词**。

## 四、边界（防滥用）

1. **网页版产出必须本地验证（编译 ＋ 测试 ＋ 真机）才算数。**
   三个层次缺一不可：编译过、测试过、真机装过。2026-10-21 的教训就摆在那儿——`反馈/feedback-开发反馈循环别走build-apk.md` 记的是「改 UI 反馈循环必须压到 10~30 秒」，靠的正是 hot reload / Preview / 局部 widget test 这条**本地**闭环，不是靠外部模型的嘴上结论。
2. **不得把「它说行」当验收。**
   它说「已测试通过」不算；它说「这个方案可行」不算。**本地跑出来的结果才算。**
3. **不得把项目私有内容贴到不可信通道。**
   网页版读的是**公网仓库/公开链接**，不是我们本地磁盘（`feedback-网页版可外包执行` §三）。需要喂料的私有内容要先判断通道可信度。
4. **它读不到仓库时（Gemini 网页版读不了 GitHub），改走 raw 材料或换通道。**
   已实测：Gemini 网页版**读不了公开 GitHub 仓库**（`参考/reference_Gemini网页版能力与限制.md` §四）；DeepSeek 官网**能读**（`chan-test` 实测，见 §八·2）。退路顺序：**换通道**（DeepSeek 网页版 / ChatGPT 镜像站）→ **改走 raw 材料**（发到公开仓的 .md 分节文件）→ **本地喂料包**。
