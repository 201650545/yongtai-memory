## 一、为什么 AI 生成的前端界面往往缺乏高级感

日常使用大语言模型（GPT、Claude、Codex 等）编写前端与课件时，AI 普遍存在**“防御性解释习惯”**：
1. **害怕用户不理解操作**：AI 缺乏对“视觉直觉”的信心，倾向于在每个交互控件四周硬塞文字说明；
2. **按钮下方加小字**：在“播放”按钮下写“点击收听标准发音”，在“录音”按钮下写“按下开启麦克风”；
3. **乱加顶部警告条与底部备注**：动辄添加“注意：请保持环境安静”、“备注：满分 100 分”；
4. **多轮对话严重退化**：第一版页面往往还算干净，但一旦人类提出修改，AI 习惯“就地打补丁”，在旁边再加一行小字备注，最终整个界面变成一份密密麻麻、廉价臃肿的“软件说明书”。

## 二、核心法则：让布局自己说话（Let the layout do the explaining）

在生成 HTML / 课件 / UI 代码时，系统性注入以下核心法则：

### 1. 消除一切次要标签（Secondary Labels）与操作提示
- 凡是用户凭借生活常识或标准图标（播放、录音、垃圾桶、编辑、勾选）就能推断出的交互，**坚决不写文字解释**；
- 严禁在按钮内或按钮下添加两行式的辅助小字。

### 2. 用视觉语言替代文本说明
- **层级自解释**：字号阶梯（38px 主词汇 vs 16px 国际音标）建立自然的视线落点；
- **色彩权重自解释**：主行动按钮（Primary Action）使用高饱和品牌色并带轻微投影，次行动按钮（Secondary Action）使用灰底或浅边框，主次立判；
- **状态动效自解释**：播放中呈现声波律动，录音中呈现呼吸光晕，胜过千言万语的状态文字；
- **空间留白自解释**：使用清晰的 `gap`（12px~24px）与内边距分离信息区块，杜绝虚线框与文字分类标签。

### 3. 多轮修改不打文字补丁
- 遇到需求变动，坚决重构布局结构与 CSS 样式，严禁在页面上原地追加“修改说明”或辅助小字。
