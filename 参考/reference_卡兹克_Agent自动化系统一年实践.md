## 二、可直接借用的做法

1. **事件中台（唯一入口）**
   - 所有事件先落到中台，统一格式：`来源 / 类型 / 对象 / 一句话摘要 / 回链`。
   - 规则集中在 `rules.json`：`when(source,types) → to(agent) / cwd / skill / ask / group / parallel / tell`。
   - 接一种新事件＝加一条规则；换模型＝改一行字。**不为每种事件写一套脚本**。
2. **中台四项附带价值**：统一去重（同一件事被重复推送时不叫醒多个 Agent）／所有消息单一出口到飞书／每条事件留底（谁接的、结论、后来怎么解决）／能一键跳回 Agent 当时的会话。
3. **本地 Agent 不暴露公网的做法**：Agent 机器上跑「接单程序」，长轮询挂在中台上（一次等 50 秒），效果接近实时推送。
4. **CI 中台五步**：审查 → 检查 → 合并 → 发布 → 核实。要点：
   - 写代码的模型（Claude）与审代码的模型（GPT）分开；审查方**只读**、不能改、不能联网、拿不到密钥。
   - **最多审 3 次**（学 Anthropic《How the Claude Code team does code review》），防无限审查。
   - **只报真会出错的问题，不报代码风格**。
   - 每个任务开全新虚拟机，跑完连机器带身份一起销毁；Agent 的代码不在主机跑。
   - 合并前审查与检查写死为仓库规则；发布后还要**回线上核实版本确实生效**，才算结束。
5. **批示口径（防注意力被吃掉）**：只把六类事推到人面前——删数据、停服、花钱、对外发消息、改产品方向、新建或轮换密钥、修改权限。
6. **两份决定文件**：「定了的事」（含原话与日期，Agent 不再问第二遍）＋「定了不做的事」（被拒过的，Agent 直接照答）。
7. **Skill ＝ 任务 SOP**：每个自动化任务配一个专属 Skill，改流程改 Skill，不动 Agent 执行逻辑。
8. **本地不云化的理由（可复用判断）**：代码仓、发布权限、飞书身份、已登录各账号的浏览器都在本地机器；上云要在每家云复制一遍登录与权限，既不安全，国内站点（微信等）在云虚拟机里也打不开。

## 三、对本人系统的接口

- 与 `D:\Work\元智能` 现有定时任务 / 指标口径的思路一致：「声明态 + 只读探针 + drift」。
- 可直接补的空缺是：**事件统一格式 + rules.json 式路由 + 事件级去重 + 单一出口**（本机目前是各任务各自播报）。
- CI 五步可作为将来任何自建仓的合并门禁模板。
