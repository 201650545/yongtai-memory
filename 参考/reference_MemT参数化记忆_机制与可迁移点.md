# MemT 1.0 参数化记忆：本质与可迁移点

> 2026-10-21 只读研究（读已存档的两篇正文，**未联网、未下权重、未部署**）
> 论文：arXiv **2610.26825**《MemT-1.0: Towards Memory-Native Evolution》（74 作者 / 66 页 / CC BY-NC-SA）
> 方案：`D:\Work\元智能\10_AI自成长引擎\docs\方案\20261021_IDEA024_MemT记忆原生_可迁移机制与落地建议.md`

## 一、本质（一句话）

**把记忆从"数据问题"改成"优化问题"**：记忆不再是每次重新注入上下文的文本，
而是模型内部**可读写的状态**（与原注意力并联，逐 token 读写、前向写入、无需微调基座）。

## 二、四个可迁移的机制（模型本身跑不动，但这四个设计能用）

| # | 机制 | 要点 |
| :-- | :-- | :-- |
| M1 | **local memory ＋ hyper memory 分离** | 动态状态 ＋ **决定"怎么写怎么读"的固定参数** ⇒ 规则层与状态层分离 |
| M2 | **四道门控** | 擦除／写入／**遗忘（控保留强度）**／输出（控记忆对当前回答的影响） |
| M3 | **Mixture-of-Storage** | 多专家共享地址、分别学读写路由 ⇒ **记忆容量可独立扩张，基座不动** |
| M4 | **自蒸馏式学习** | 老师看完整原文，学生只看"本轮＋记忆" ⇒ 目标是**两者给出同样的回答** |

## 四、落到本机系统的三个改造点（详见方案文件）

1. **记忆条目要能"被取代"，不只是追加** —— 证据：2026-10-21 IDEA-026 审计抓出 8 条 P0，
   其中 4 条是同一病：**资产已删/已废弃，文档与索引仍描述成"活的"** ⇒ 这就是"只有写入、没有擦除"的症状。
   落地：frontmatter 加 `status: superseded` ＋ `superseded_by`，索引**保留指针但不再当活能力暴露**。
2. **规则层自己也会过期** ⇒ 超记忆（`AGENTS.md`）也要有"被哪条取代"的关系，不只是"再加一条"。
3. **"不看原文能否复现答案"＝该不该入库的判据** —— 与他已定的「每条建议都能解释为什么」「记忆只留活的东西」同源。

论文（arXiv 2610.26825v2）附录 G 的四个案例，直接对应他系统的四个真问题：

| 论文一手 | 对应他的问题 |
| :-- | :-- |
| G.2 问"从未提过的生日" ⇒ 答 **"I don't know."**（6 token） | **"不知道"必须是一等答案**（今天我犯的错：型号误配却报"已接入"） |
| G.3 链式规则缺一前提 ⇒ 答"不可领"（不多推） | **前提检查**（"免费性闸门 7 步"同源） |
| G.4 已定改动 vs 在议提议 ⇒ 只报已定、排除提议 | 想法池 `captured/assigned/done` 状态机制**方向已被验证** ✅ |
| G.1 属性不串味（宁波/红工具箱/蓝工牌不跑到陈伟名下） | 多项目/多账号记忆必须**带归属标签** |

**论文机制原话**："A commit reads the incoming turns and writes their content into the slot, and **the original text is not carried forward**.
**What the model can answer therefore depends on the writes.**"
⇒ **能答什么取决于写进去了什么** ⇒ 记忆系统的质量在"写入策略"，不在"存量"。

**最重要的一条可落地洞察**：论文 6.4 用**消融**衡量每个组件的价值 ⇒ 他的轻量版是
**给 `AGENTS.md` 每条规则做消融**（关掉某条规则，任务成功率是否变化），
用 `:8787` 的 `logs` 表就能统计成功率 ⇒ **这就是 IDEA-026 审计的科学解法**，
也回答了"记忆项目怎么优化"：**让读写策略变成可测量、可淘汰的对象**，而不是把记忆搬进参数。

## 六、落地门槛（为什么不做部署）

`Nano` 36B/3B 激活/可训练记忆参数 **451M**/动态状态 10M；`Flash` 288B/17B/**3.61B**/336M。
本机 2 核 2G ECS ＋ PC，且这是**基座架构级重训**（34B tokens 两阶段训练），
不是加条规则能做的事 ⇒ **只借鉴机制，不部署**。

### 7.3 ★ 最值钱的一条（论文级背书，此前无人指出）

论文 **§7.2–§7.4 比较过"检索到的操作经验放进文本上下文"与"放进神经记忆"**：两种方式在 Agent 任务中**表现可比**，**文本经验在部分设置下还更好**（二手解读也记着同一句：SWE-bench Verified 三次全对率 54.0%→61.6%，「**和把经验直接塞进对话里一样**」）。

⇒ **「不能训练基座、只能改明文文件与流程」这条约束本身有论文级正当性**，不是妥协。
⇒ 「经验内化」的正确形态**不是"变成规则"**，而是**"变成带适用条件的可检索经验条目"**（`condition/action/verification/source`）。
