# 信息源溯源：一手优先

> **规矩**（2026-10-21 16:35 郭老师定，已写进 `C:\Users\郭永涛\AGENTS.md` **第 19 条**）：
> 「如果以后我再发文章、发这些笔记，他们一定是**二道贩子**。我们一定要通过他们的推荐，找到原出处，
> 把**原论文、原机的核心内容**找过来。」

## 一、为什么要（实测证据）

2026-10-21 读 MemT-1.0 时**实测踩到**：二手解读（赛博禅心）写
「明文记经验，记下 1、2、3 条，就永远只有这三条；而经验写进参数之后，模型有可能把这三条融到一起，**自己得出第 4 条**」——
**论文原话并不是这个**。论文说的是：*"By internalizing **retrieved procedural experience**, MemT-1.0 improves task success on agentic tasks."*
（把**检索到的程序性经验内化**后 agentic 任务成功率提升。）

⇒ **二手解读会把推论写成结论**，而且**看起来完全合理**，不交叉核对就发现不了。
⇒ 一手才是"可核对的依据"，二手只是"找到一手的线索"。

## 二、一手清单（按可信度从高到低）

| 类型 | 例子 | 怎么找 |
| :-- | :-- | :-- |
| **论文原文** | MemT-1.0 = arXiv **2610.26825** | arXiv abs 页 → `HTML (experimental)` 全文；`/src/` 有 TeX 源码；PDF 需本地解析 |
| **官方代码仓** | `github.com/MemTensor/MemT-1.0` | `gh api repos/<owner>/<repo>/readme --jq .content`（免克隆取 README）；`contents` 看目录 |
| **模型卡 / 官方文档** | `huggingface.co/<org>/<model>` | 直接 web_fetch；模型卡常有**限制与用法**（二手不会写这些） |
| **接口规范** | `aihot.news/openapi-v1.json`、`lark-cli schema <service>.<resource>.<method>` | 有 schema 就别猜参数 |
| **自描述说明** | `aihot.news/api/v1/agent`（给 Agent 的使用说明） | 有些服务自带"怎么用我"的说明端点 |
| **标准文本** | 飞书卡片规范、OpenAI API 文档 | 官方文档站 |

⚠️ **禁止用 `web_search`**（AGENTS 第 6 条，烧钱硬禁）。已知 URL 用 `web_fetch`；GitHub 用 `gh api`。

## 三、溯源工作法（照着做）

1. **先读二手的"参考/出处"段**——它通常给出论文名、arXiv 号、GitHub 链接、作者。
2. **把线索换成一手 URL**：论文名 → arXiv 搜编号；产品名 → 官方仓/官方文档。
3. **读一手，只记一手明确写了的东西**；二手有的、一手没有 ⇒ **不写进结论**（可标注"二手称 X，一手未见"）。
4. **一手读不到就明说读不到**（读的是摘要页还是全文？哪几节？），**不拿二手充数**。
5. **一手与二手冲突 ⇒ 以一手为准**，并在记忆里留订正记录（我 10-21 就订正过一条）。
