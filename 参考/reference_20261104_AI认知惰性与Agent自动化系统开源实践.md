# AI 认知惰性反思与 Agent 自动化系统开源实践

## 一、文章一与二：Addy Osmani《智能体越顺手，人的批判性思维退化得越快》（量子位/推特长文）

### 1. 核心现象与痛点
- **认知退化三部曲**：从「认知卸载」（把具体执行交出去，自己懂任务和判断）→ 滑向「判断让渡」（AI 的答案逐渐变成下一步的默认依据）→ 最终陷入「认知投降（Cognitive Surrender）」（沃顿商学院概念：全部听 AI 的，连判断也拱手相让，活成一枚“回车键”）。
- **两笔隐形债务**：
  - **意图债（Intent Debt）**：提问者自己没想清楚需求、边界和取舍，由 AI 擅自替人类做决定；
  - **理解债（Comprehension Debt）**：代码大厦越垒越高、功能越来越复杂，但人类对系统内部结构的理解完全停滞，一旦出问题谁都修不动。
- **监督悖论（Supervision Paradox）**：想挑出 AI 的低级/高级漏洞，恰恰依赖那些因为长期使用 AI 而正在逐步退化的底层手艺。

### 2. 破局妙招（刻意找不痛快）
1. **反向测验**：让 Agent 总结修改后，出 3 道题考人类开发者，全部答对才准合并代码。
2. **提问前立假设与清单**：先动脑列出目标、限制、不要做什么，连续 2 轮对不上味必须推倒重写需求，不硬堆 Prompt。
3. **交代隐式决定**：追问 Agent“你做了哪些我未明确授权的决定？哪些地方依赖了假设？还有什么没测？”
4. **测试绿不等于没 bug**：检查实际跑了什么用例，警惕边界条件缺失的“假绿色”。
5. **保留原始依据**：多 Agent 协作传话会逐级稀释信息，必须留存一手数据与真机日志。
6. **古法手搓校准**：每周挑一件核心活关闭 Agent 手写一次，给大脑和手艺校准。

## 二、文章三：数字生命卡兹克《开源我这折腾了1年的「Agent自动化系统」》（Agent-Autoloop）

- **开源仓库**：`https://github.com/KKKKhazix/agent-autoloop`
- **项目定位**：极简微内核 + 一切皆插件（借鉴 Pi 极简内核与 DeepSeek Harness 设计理念）。

### 1. 核心架构（Autoloop 中台）
- **1600 行 Node 零外部依赖**：启动 <0.1s，平时内存约 60MB。
- **架构硬边界**：内核只做 4 件事（收事件、按 rules.json 分活、派活给 Agent、记账溯源）。**内核绝不发起外部网络请求，绝不写死任何具体模型或 Agent 名字**。

### 2. 四大工程避坑机制
1. **挂起零消耗（Suspension Zero-Cost）**：遇到需要人工拍板（如删库、发通知、花钱），发完卡片后进程立即退出下班、彻底释放资源；三天不回零消耗，点击后读档恢复，杜绝轮询空耗。
2. **事件溯源（Event Sourcing）**：单向追加账本（类似银行流水），事件只往后写、不改历史；断电/断网自动幂等重放，不重复执行写入。一条命令 `agent-autoloop why <id>` 全景复盘。
3. **指令与数据分离（Instruction-Data Separation）**：外部不可信内容（Issue、用户反馈、外部网页）放入独立 data 文件，与系统 Prompt 物理隔离，防注入攻击。
4. **跳数熔断（Hop Limit / TTL）**：多 Agent 唤醒链条每跳递减，超过 8 跳自动硬熔断并报卡片报警，防止死循环无限烧额度。

## 三、对齐我们本机的工程实践与映射关系

| 外部概念 / 机制 | 对应我们本机的既有资产 / 规则 | 本次启示与差距 |
| :--- | :--- | :--- |
| **防认知投降** | 郭老师定下的 14 条硬约束、像素级取色、先检索后动手 | 保持“做完先看命令与原始输出”，复杂架构变更让 AI 自述隐式假设 |
| **极简微内核** | `AGENTS.md` 运行时微内核路由（P0-P3） | 保持内核纯指针，不往内核塞具体外部业务 |
| **挂起零消耗** | 飞书审批卡片、计划任务与异步任务状态机 | 会话收工 0 残留（铁律 5）；未来长流程工单可采用存档读档 |
| **单向事件账本** | 飞书多维表格 5 表联动、`轮次记录/YYYY-MM-DD.md` | 本地执行 log 保持只追加，每次决策留出处证据卡片 |
| **跳数熔断** | 铁律 10（禁真模型对比压测）、P2 四级闸门 | 在多 Agent 或复杂脚本中显式加上 loop_count 上限防失控 |
