# 网页版送审与出码协议

> 一句话：**网页版负责"想"和"写"，本地子 agent 负责"放"和"验"；网页版产出未经本地验证命令跑通，一律不算交付。**
>
> 本条只写方法，不写代码。所有落地动作（写文件、跑命令）一律由本地子 agent 执行。

## 一、适用场景

### 该用网页版（DeepSeek 网页版 / GPT 镜像站）

1. **出方案 / 出架构**：要一个"外部高智力模型"的独立视角；材料是公开 URL，或你贴进对话的文本。
2. **出完整代码**：模块边界清晰、输入输出明确、能靠"完整贴出若干个关键文件全文"把上下文喂饱的活。
3. **代码审查**：对着你贴出的代码挑毛病——空指针、边界、并发、性能、命名。
4. **需要一张白纸**：本地 agent 已被自己的实现锚定了，网页版没有本地上下文偏见，适合当第三方视角。

### 该用本地子 agent

1. **落盘**：把网页版产出的文本写进真实文件、放进真实目录。
2. **跑测试 / 跑构建 / 跑验证命令**：任何"跑一下才知道对不对"的判定。
3. **集成**：把新模块接进现有调用链，解决 import 路径、相对路径、编码、依赖声明。
4. **debug**：看真实报错、真实堆栈、真实中间产物之后再改。
5. **需要访问私有仓库 / 本地磁盘 / 本地数据 / 环境变量**的活——网页版根本够不着。

### 一句话判据

> **"需要模型用脑子的部分"交给网页版；"需要机器用脚的部分"交给子 agent。**
>
> 中间必须有人（子 agent）做交接：网页版说"这是正确做法"，本地跑通才算数。

## 二、三个硬边界

### 边界一：网页版读不到本地磁盘

- 它**没有**你的文件系统视图：`D:\` 下有什么、哪个文件是最新版、配置文件里写了什么，它都不知道。
- 它只能读两类材料：① **公开可访问的 URL**（公开 GitHub 仓、公开文档、公开网页）；② **你贴进对话框的文本**（粘贴的代码、日志、报错栈）。
- 私有仓库等同于不存在。仓库不公开，它就读不到——只能把材料贴出来（贴关键文件，不是整个仓库）。
- 推论：**任何"以路径指代内容"的做法都无效**。对它说 `见 core/subtitle.py` 和说 `见 core/subtitle.py` 而不贴内容，效果一样：它看不到。

### 边界二：网页版跑不了本地代码和数据

- 它**不能**执行你的 Python、不能跑 ffmpeg、不能读你的 CSV/JSON 数据、不能看你的测试结果。
- 它的输出形态只有两种：**文本**和**文本里的代码块**。
- 所以凡是"必须看运行结果才能判断"的环节，都不能放在网页版这一侧。

### 边界三：ChatGPT 镜像站取回通道当前故障，修好前不可用

- 现象：**发送成功但抓回失败**——三闸（Chat 标签 / 模型 `6` / 顶档 `High`）都过了，`stop:true`，但 DOM 里只有几十个字符，轮询数分钟长度不稳定，答案取不回来。
- 佐证：`D:\记忆\项目\project_想法池.md:621` 已独立记过同一条故障（三闸通过、发送成功、抓回超时）。
- 处置：**修好前不可用**。当前可用的网页版通道是 **DeepSeek 官网**（实测能读 GitHub 公开仓，原文贴出、可逐字核对；见 `D:\记忆\参考\reference-deepseek-web-送审实战沉淀-20261021.md`）。
- 同源既有坑，一并记住：
  - 两条浏览器通道**不能并行**（共用 Chrome 活动标签，opencli 会话一次只绑一个标签）⇒ 必须**串行**：先 DeepSeek，答完再镜像站。
  - DeepSeek 侧 `ds_ask.py` 内置的"输出停 30 秒就刷新页面重取"会**打断联网阅读**，一次读取作废 ⇒ 取答前去掉该刷新，等待放宽到 ~220s。
  - PowerShell 5.1 传带引号的多行参数会被**截断** ⇒ 改用 `$env:` 变量传参。
  - DeepSeek 取答前必须 `activate_window` + `tab select`；标签 `visibilityState=hidden` 时消息节点恒为 0。

## 三、分工表

| 环节 | 网页版（DeepSeek 网页版 / GPT 镜像站） | 本地子 agent |
|---|---|---|
| 出方案 | ✅ 主力：独立视角，拿公开 URL / 贴入文本做全量分析 | ⭕ 只做整理与归档 |
| 出完整代码 | ✅ 主力：按提示词模板给"绝对路径 + 完整内容" | ⭕ 只做原样落盘 |
| 代码审查 | ✅ 主力：挑空指针 / 边界 / 并发 / 性能 | ⭕ 只做记录问题清单 |
| 落盘 | ❌ 做不到：读不到本地磁盘 | ✅ 唯一执行方：建文件、写内容、保持编码与换行 |
| 跑测试 | ❌ 做不到：跑不了本地代码 | ✅ 唯一执行方：跑验证命令、贴真实输出 |
| 集成 | ❌ 做不到：不知道真实 import 链与目录结构 | ✅ 唯一执行方：接调用链、修路径 / 依赖声明 |
| debug | ⭕ 只能对**你贴出来的报错栈**给意见 | ✅ 唯一执行方：读真实堆栈、看真实中间产物、改真实文件 |
| 验收判定 | ❌ 无权判定 | ✅ 唯一执行方：**验证命令跑通才算采用** |

## 四、提示词模板

原文照抄（不要改写占位符）：

```
【项目】<一句话定位>。Windows，Python 3.x + ffmpeg + ASS 字幕。
【现有代码】<贴 1-2 个关键文件全文，不要贴整个仓库>
【约束】不许引入新依赖；不许改 <某个函数>；必须兼容 <某个格式>
【任务】实现 <一个具体模块>，输入 <X>，输出 <Y>
【输出格式】每文件给绝对路径 + 完整内容，禁止用 ... 省略；最后给一段本地验证命令
【禁止】编造不存在的 API；假设某个文件存在；用伪代码代替实现
```

模板用法说明（说明不改动模板本身）：

- 【项目】必须是一句话定位，把技术栈与运行平台说清（Windows / Python 版本 / ffmpeg / ASS 字幕这一套）。技术栈不写，模型会按 Linux / Node 的习惯写。
- 【现有代码】只贴 1-2 个**关键文件全文**，不要贴整个仓库——贴多了上下文被稀释、响应变慢甚至中途截断。
- 【约束】三条都要落到**具体的函数名**和**具体的格式**，不要写"不要改核心逻辑"这种没法判定的句子。
- 【任务】一次一个模块，输入输出用 `<X>` `<Y>` 写死，别写"处理一下数据"这种描述。
- 【输出格式】四项缺一不可：省了"绝对路径"，子 agent 要自己猜该写哪；省了"禁止用 `...` 省略"，会拿到截断稿；省了"本地验证命令"，就没有"跑通才算采用"的判据。
- 【禁止】把第五节三条写进提示词，是让模型在**生成时**就不越界，而不是事后再检查。

## 五、三条禁止项各自的理由

### 禁止一：编造不存在的 API

**为什么会发生**：网页版看不到你的本地依赖清单，只能按"训练数据里 Python 生态常见什么"来猜；而猜一个看起来很合理的函数名（`subprocess.run_ffmpeg(...)`、`moviepy.ffmpeg.extract_subtitle(...)`）比老实说"我不确定"更"有用"，所以模型倾向给出确定语气。本地一 import 就 `ImportError` / `AttributeError`。

**怎么挡**：提示词【禁止】明写；【约束】锁死依赖与版本；【输出格式】要求"最后给一段本地验证命令"——模型自己写的验证命令一跑，就把自己编的假 API 暴露了。

### 禁止二：假设某个文件存在

**为什么会发生**：网页版看不见仓库结构，只能根据项目名和常见工程布局**推断**一个合理目录树（`utils/`、`src/`、`core/`）；推断出的路径读起来非常自然，于是被当成事实写进代码。而这些文件在真实仓库里要么不存在，要么名字差一点（`subtitle.py` vs `subtitles.py`），落盘时不是覆盖就是把项目结构搞乱。

**怎么挡**：提示词【禁止】明写；【现有代码】贴的是真实文件全文，模型猜路径的空间随之缩小；子 agent 落盘前先核对路径是否真实存在，不存在就退回让网页版补齐材料，而不是自己"顺手建一个"。

### 禁止三：用伪代码代替实现

**为什么会发生**：输出长代码时模型会"省力"，把循环体、错误分支、边界处理写成 `...` / `# TODO` / `pass`，既短又显得清楚——它无法预知你要多长，也无法确认被省略的段落对你重不重要。

**怎么挡**：提示词【输出格式】要求"完整内容，禁止用 `...` 省略"，【禁止】明写"用伪代码代替实现"；子 agent 收到含 `...` / `TODO` / `pass` 占位的稿子直接退回，不用"我来补"——补出来的东西网页版没审过，等于没送审。

## 六、取回与验证流程

五步，缺一不可：

1. **网页版产出**：按第四节的模板发问，拿到含"绝对路径 + 完整内容 + 验证命令"的完整回复。**先自查三处**：有没有 `...` / `TODO` / `pass` 占位；有没有出现你没贴过的文件路径；验证命令里引用的库是否在【约束】允许的范围内。
2. **复制到本地临时位置**：把网页版回复**整段**复制到本地一个临时文件（如 `D:\记忆\_inbox\送审方法论\_tmp\`，或工作区的临时目录），**先不落进项目目录**。这一层是隔离带——验证通过前，网页版产出不是项目的一部分。
3. **子 agent 落盘**：由子 agent 按回复里给的**绝对路径**把每个文件写到项目里的真实位置（注意 UTF-8 编码、换行不乱、目录不存在就建）。子 agent 只做"照抄"，不做"改写"。
4. **子 agent 跑验证命令**：跑网页版给的那段本地验证命令，以及项目自己的测试。**必须贴出当轮真实输出**——没有输出的"已跑通"等于没跑。
5. **跑通才算采用**：验证命令通过 ⇒ 清掉临时文件、产出计为交付；跑不通 ⇒ **带着真实报错回到网页版续问**（贴报错栈，复用同一会话别重开），一轮解决不了就转本地子 agent 直接 debug。

失败分支的处置：

- **网页版取不回**（ChatGPT 镜像站当前就是这状态）⇒ 别在网页版上死磕，直接换通道（DeepSeek 官网），或改由本地子 agent 出码。
- **网页版改不对**（连续两轮还错）⇒ 停止网页版回路，把问题连同真实报错交给本地子 agent；网页版只保留"出方案 / 做审查"的用法。
- **网页版要求"跑一下确认"** ⇒ 它做不到，别要求它做；让子 agent 跑，然后把真实结果贴回去。
- **网页版说"我不能访问你的文件"** ⇒ 这是边界一在正常工作，不是故障；把需要的文件**贴**进去，或推到公开仓用 URL 指过去。
