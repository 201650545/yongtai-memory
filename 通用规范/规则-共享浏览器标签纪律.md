# 共享浏览器标签纪律（多 Agent 共存）

> 投递任务：共享浏览器标签纪律（记忆库 inbox 写入任务）。
> 来源：同上。
> 时间：2026-10-22。
> 去向：本条为**新建条目**（去重检索结论见文末「去重检索记录」），请整理会话判断正式归档位置。

## 一、问题

多个会话 / 多个 agent 共用同一个浏览器。历史上出现过：

- 抢用别人的标签；
- 把自己的输出写进别人的会话（RECOVER 到别的会话并覆盖输出文件）；
- 任务结束后不关标签，把浏览器撑爆（开出一堆残留标签）。

## 二、硬规则

1. 一律新开自己的标签页，从空标签开始。
2. 绝不接手、绝不激活、绝不复用任何已存在的标签。共享浏览器里无法可靠判断标签归属，"复用"等于抢占。
3. `tab list` 只能用于只读确认（确认自己没有残留），不能用来挑选"可复用"的标签。
4. 任务结束前关掉自己开的每一个标签；返回格式里必须报「标签：开了 N / 关了 N / 剩 N」，N 必须为 0。
5. 一轮任务最多开 1 个新标签。需要开第 2 个 = 做错了，必须停下报告，不许开。
6. 只关自己开的。别人的标签，即使看起来是废弃的，也不动。

## 三、旧写法的前提已失效（不是旧规矩错了）

- 旧结论：「复用原有标签页，不要反复新开」「执行完不许关掉标签/会话」。出处：流程\workflow_ai_wendabao_open.md 规则零（2026-09-15）、反馈\feedback_gpt_mirror_subagent_flow.md 第 2 条（2026-09-03）。
- 旧结论成立的前提：一个 agent 独占浏览器。当时要解决的问题是"标签堆满"与"每次重跑整条流程 2-3 分钟"，所以在单 agent 前提下复用是对的。
- 前提失效条件：出现多个 agent / 多个会话并行共用同一个浏览器。此时"复用"等同于抢占别人的标签。
- 结论：旧条不需要否定，需要补前提。处置方案（2026-10-22 郭老师选定 A 方案）：直接修改规则零的措辞，而不是在别处声明废止。因为正式文档留旧、inbox 写新的，会制造第二份冲突。
- 旧写法：「开之前先 tab list 看有没有能复用的，能复用就不新开。」该写法的前提已失效——共享浏览器无法判定归属，复用即抢占。

## 四、适用范围

所有会驱动浏览器的 agent 与 skill，包括但不限于：external-model-review（镜像站送审）、deepseek-web-consult（官网送审）、opencli-browser-stable-roundtrip、computer-use、xhs-ops。派活时这条必须逐条写进子 agent 的 prompt，不能只在 skill 里写一遍就算。

## 五、恢复锚点（发送前必须记录）

1. 子 Agent 驱动浏览器执行任务时，必须在**发送消息之前**记录两样东西：
   - 目标网址全文（含路由 hash、会话 id 等一切能定位的片段）
   - 该页面的标题，以及对话历史列表里显示的会话标题（标题可能被截断，要同时记"界面上看到的前 20 字"与"完整标题"）
2. 为什么必须发送前记：标签随时可能被别的会话抢占或关闭。抢占一旦发生，机会就没有了，事后再补是补不出来的。
3. 写到哪里：产物文件最前面单开一节「锚点」，纯文本两行，一行 URL 一行标题。不要只写在对话里，对话会丢。
4. 用途：标签被抢、会话丢失时，用 URL 直接导航回去；URL 失效时，用会话标题去历史对话列表里匹配（镜像站/官网的对话列表一般按时间倒序，配合标题能定位）。
5. 强制：任务成功但没记锚点 = 交付不合格。锚点是交付物的一部分，不是可选项。
