# 00 · 存档与内化（跨项目通用，最高优先）

> 版本：**v1.1**（2026-10-08 郭老师口述定稿）
> **位置说明**：本文件是这条规矩的**唯一真源**，在 `D:\记忆\通用规范\00-存档与内化.md`。Agent 从 `D:\记忆\索引.md` 进记忆库即可命中，不需要经过 `D:\Work`。

## 一、存档只留最近一个星期

- 任何"存档／归档／历史记录"性质的文件，**只保留最近 7 天**。
- **超过 7 天自动删除**，不询问、不提醒、不"先归档着"。
- 判定基准用**文件最后一次写入日期**（不是创建日期）。
- 适用范围：轮次流水（rounds）、交接档、过程日志、临时验证产物、一次性排查脚本、咨询原文。

## 二、外部模型产出物：整理完即删

> 原话（2026-10-08）："这种从原文规范搬过来的内容根本没必要保留。它生成之后，我应该把它整理到自己这里，内化成我的规范、我的风格；整理完之后，它就没用了，就应该删除。"

执行拆解：

1. **原始产出物**（GPT/其他高智力模型的咨询原文、外部规范原文、方案原稿）**只作为草稿存在**。
2. 郭老师/Agent 把其中**有用的部分内化**进自己的规范、记忆条目、项目文档。
3. **内化完成的那一刻，就是删除原材料的时刻**——不留档、不备份、不"以防万一"。
4. 判断标准：**它是否已经被消化进别处**。消化了就删；没消化完就别删（那说明还没整理）。

## 三、为什么这条排第一

它是元智能里"L1/L2/L3 沉淀"最容易走偏的地方：**沉淀一旦变成"存着"，就会变成债务**——没人读、没人维护、还占地方，最后变成第二个没人看的系统（`meta-intelligence-facts` 就是活例子：投影了却零消费）。

**沉淀的终点不是"存下来"，是"用出去"。**

## 四、执行约定

| 场景 | 动作 |
|---|---|
| 会话结束前 | 只回写**结论与规则**；过程流水不落盘 |
| 需要留过程 | 只留 `D:\记忆\调度大脑记忆\` 里对应的**结论条目**，过程写进条目的时间线 |
| 收到外部模型长文 | 提炼 → 内化 → 删原文（不建"原文归档"目录） |
| 每周 | `session_close_lint.mjs` 报"存档超期"（见下），清掉超 7 天的 |

> 配套：每日收尾自检（`D:\Work\元智能\runners\session_close_lint.mjs`）已包含 git 卫生与投影检查；**存档超期检查待加**，因为它需要按"目录用途"判定哪些是存档，比现有 7 项复杂，先记在此处不假装已实现。

**How to apply:** 写任何文件前先问一句"这是结论还是过程"。过程默认不落盘；落了也不留过 7 天。
