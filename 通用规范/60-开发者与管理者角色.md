## 1. 我的角色是什么（三合一）

我是逆天主题这类长期创意项目的**唯一承担者**，同时是三重身份：

| 身份 | 我负责什么 | 我最容易犯的错 |
|---|---|---|
| **开发者** | 把想法变成能跑的东西，代码、美术调度、技术落地 | 陷进技术细节，忘了"这东西要有人用" |
| **管理者** | 定目标、排优先级、控风险、验收，决定做什么不做什么 | 只管理"任务量"，没管理"方向对不对" |
| **学习者** | 从每一轮做成/做砸里提炼方法，迭代自己 | 重复踩坑，不沉淀成规则 |

**三者永不拆开**。做东西时我是开发者，做选择时我是管理者，做完后我是学习者。

---

## 2. 核心理念（GPT 给你最重要的一句话）

> **你不是在"完成一个设计"，你是在"持续验证一个有生命力的产品"。**
> 最大风险不是技术难，而是——**花一年做出一个没人玩过的大系统。**

所以判定我做得对不对，不看"我写了多少设计文档/做了多少资产"，而看**"这条路径有没有真的被反复使用"**。

## 3. 方法心智模型（三条腿站着，别只靠一条）

### 3.1 节奏观：先养核心循环，再扩世界
- 第一个版本不叫游戏，叫「**最小可体验原型**」：一次行为 → 一个即时反馈 → 一段可见结果，闭环能跑通即可。
- **明确划掉**暂不做的东西（战斗/复杂动画/完整剧情/多角色/商城/社交），用 `docs/否不做清单` 记录，防野心蔓延。
- 用 **90 天验证周期**，第一个周期只回答一件事：**"这件事能不能让用户持续回来？"** 能，才扩建；不能，先改产品不是改代码。

### 3.2 创造力观：提防「创造者偏见」
自己觉得有意思 ≠ 别人一定喜欢。三招破解：
1. **三身份切换**（别同时用）：
   - 🎨 创作者：允许幻想、发散
   - 📋 产品经理：问"用户为什么需要？""酷能让用户回来吗？"
   - 🧪 测试玩家：模拟陌生人——"5 秒看懂吗？30 秒有反馈吗？10 分钟想继续吗？"
2. **三区验收清单**：产品价值 / 用户体验 / 技术——**三区全过才开发，不过就不开发**（清单模板见附表）。
3. **强制外部反馈**：每月找 3 程序员 + 3 玩家试玩；问"第一次打开觉得目标是什么 / 什么时候想关 / 哪里浪费时间"。**观察他们怎么用，比听他们说"不错"重要。**

### 3.3 规划观：大方向设计驱动，小细节原型驱动
- **高确定性且改错成本高**（世界观 / 修仙逻辑 / Coding 映射 / 产品路线）→ 先设计文档
- **低确定性**（喜欢什么反馈 / 突破频率 / 数值爽不爽 / UI 沉浸感）→ **直接做，别写长文档**
- 判断规则一问你给自己：**"如果这个错了，修改成本大不大？"** 大→先文档；小→先原型。
- 决定性认知：**设计文档不是承诺书，是假设列表。** 改动它不是失败，是学习。

## 5. 长期运转：反馈 → 分析 → 优化闭环（产品落地后怎么活 1 年+）

> 依据镜像版 GPT Extended 长期运营咨询（完整原文 `C:\Users\Public\nitian_ops_reply.txt`）。核心：产品不是"做完"，是"持续在运转"，靠一条反馈驱动循环活着。**单兵版 vs 企业版只差"埋点+团队"，循环本身一样。**

### 5.1 节奏：固定节奏 + 小批量，弃"大版本驱动"
- 每次开发只解 **1 个问题**（0.5–2 天）；**每周小发布**（哪怕只修 bug / 删个按钮）；每 2 周看反馈删需求；每月一次体力检；每季度判扩张或收缩。
- **主分支始终可发布**——任何功能超 2–3 天不能独立上线，就切小，别憋大版本憋死自己。

### 5.2 反馈系统（单兵无埋点）：只做极简事件日志 + 漏斗
- 无需企业级埋点。只记**关键状态变化**的极简事件日志（JSONL/SQLite）：启动 / 首入核心玩法 / 首完成闭环 / 错误 / 退出。
- 不看 DAU，看**漏斗**：`打开 → 建角色 → 首修炼 → 首次 Coding → 拿到奖励 → 二次回来`。哪一步大量消失，哪一步就是问题。
- 另加：游戏内一键反馈、退出原因、后台驾驶舱（把漏斗和日志可视化的简单页面，自己看得见状态）。

### 5.3 分析 → 优化：分四类、前后对照、先修机制
- 收到的反馈先归 4 类：**阻断 > 摩擦 > 价值不足 > 愿望**，按此顺序处理。
- 无 A/B 时用**前后对照 + 成功条件**验证：改前记下现象，改后再看，真变好才叫优化。
- **优先修机制，不优先加内容**——机制顺了，内容才有意义。

### 5.4 迭代不杀死项目：三层系统 + 定期删
- 最大敌人是"**野心债 / 产品债**"。任何新功能进 Parking Lot 前，必须先答"**它解决哪个已观察到的具体问题**"——答不出就拦下。
- **三层系统**：核心 / 支撑 / 实验。实验层永远不侵入核心层。
- 每月一次**复杂度审计**：主动删没人用的功能。
- **保证可回滚**：独立 commit、打 tag、存档 migration、feature flag。

### 5.5 单兵执行节奏（三级）
| 级 | 做什么 |
|---|---|
| **每周** | 看 session 记录 → 修 1 个阻断 → 自测 → commit → tag → 小发布 |
| **每两周** | 查流失点 → 删需求 |
| **每月** | 验备份 / 验老存档 / 验新用户完整闭环 |

**公式（背下来）**：极小核心闭环 × 可观察 × 小步修改 × 可验证 × 可回滚 × 定期删东西。

**最该先做的 3 件事**：① 建 Event Log ② 做一个 /debug 后台驾驶舱 ③ 建立固定的"小修发布循环"（心理闭环：发现问题 → 修 → 上线 → 再观察）。

## 6. 我的四个贴墙原则（不改）

1. **管理风险，不管理任务** —— 风险 = "做了一年发现没人需要"，不是"这周没做够 N 个小时"。
2. **先证明有人愿循环，再扩建世界** —— 游戏世界是放大器，不是发动机。
3. **设计文档是假设列表，不是承诺书。**
4. **限制野心，不限制想象** —— 今天只允许做到"一次 Coding = 一次修炼反馈"，想象可以飞到很远，**这周该做的就那么一条纵线**。
