# 10 · 协作规范（跨项目通用）

## 角色分工

- **人类**：拍板方向、验收关键资产、批准对外动作（建仓库/推送/对外发消息）
- **本地 Agent（Qoder）**：任务编排、批量执行、验收落盘、文档与仓库维护
- **外部模型协作者（GPT 等）**：凭公开仓库掌握项目全貌，自主设计产出，打包交付

## 镜像站协作协议（vip-14 GPT）

1. **Extended 红线**：每次发送前必须核实输入框旁按钮文字为 `Extended` 才允许点发送
2. **单系统单消息**：一条 Extended 消息只做一个系统级任务（某系统全部形态），携带该系统底图；禁止逐张连发刷屏
3. **交付形式**：zip 优先（用户可直接下载）；Agent 侧从图片消息逐张提取落盘验收
4. **防虚报条款**：批量任务提示词必须包含「只有当每个文件名都对应一次真实成功的图片工具调用后，才允许说完成」
5. **验收落盘管线**：conversation JSON 提取 asset_pointer → 签名 URL → 本机中转服务器 `POST /save/中文文件名` → 目检 → 改名入册

## 执行纪律

- 设计 → 外部评审 → 人类拍板 → 逐次授权才动代码
- 编号方案获批后按数字顺序直接执行，不再反复确认顺序
- 新任务先登记看板再做；不虚报进度，失败如实列缺失清单

## 2026-10-10 补充：多 Agent 并行时的两条硬纪律

> 这两条是 2026-10-09~10 三个 Agent 同夜并行时**真实撞出来的**，不是预设。
> 触发背景：那晚两个 Agent 同时在 `D:\Work` / `D:\记忆` 上收死链，出现"按旧读数动手"和"改了却报成功"两类事故。

### 1. 断言必须附当轮验证输出

**任何"已修复 / 已完成 / 已删除"的结论，必须附一条当轮跑出来的验证命令输出。没有输出的就是猜的。**

- 判定动作是否生效，用**当轮跑的 `Test-Path` / 哈希 / grep**���不是"命令没报错"就当成了。
- 反例（真实发生过）：`Remove-Item` 对拼错的注册表路径静默成功、脚本自检"✓ 已删除"但复核时条目还在。
- 同理，"读数"有时效：另一个 Agent 在你上一分钟读完之后改了盘（实测 mtime 落在并发窗口内），**动手前重新读一次**。

### 2. 职责线与文件归属：只碰自己碰过的

- **同一批文件被多个 Agent 并行改动时，各自只`git add` 自己碰过的文件**，不替别人提交（规矩同 70 号"不替别人提交"）。
- 交叉引用的文件（如生成物 + 生成源、指针 + 被指内容）**必须一次改齐**，否则改了生成物会被下次生成覆盖。
- 归属不明的改动**宁可留着不提交**，并明确告诉对方"这里有别人的未提交改动"，不要替它决定。
