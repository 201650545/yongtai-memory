# 50 · 知识管理三工具规范（Obsidian / GitHub / 飞书）

> 版本：**v1.0**（2026-09-03，依据镜像版 extend 模式咨询定稿，见 `_tmp/gpt_answer_three_tools_extend_final.md`）
> 用途：定死三个知识工具的职责边界，避免多库打架、重复编辑、隐私泄露。所有项目/记忆/文档遵守。

## 0. 一条核心法则（SSOT 的唯一正确理解）

**不要追求“全系统只有一个真源”，要做到“同一种数据只有一个可写真源，其余全部是镜像 / 投影 / 缓存 / 审计”。**

- 可写 = 允许人工编辑、是最终事实来源
- 镜像 / 投影 / 缓存 = 只读派生，禁止往上反向写

## 1. 三工具各一句定死

| 工具 | 定位 | 只承载 |
|---|---|---|
| **Obsidian** | 人工知识的**主编辑工作区 + 本地真源** | 规范 / 项目文档 / 台账 / 个人记忆 / 决策记录 |
| **GitHub** | **版本历史 + 异地镜像 + AI 公共读取面**（Published Source / AI-readable Mirror） | 从本地发布出去的镜像，**不是第二编辑真源** |
| **飞书** | **结构化数据采集/管理界面 + 数据桥**（Structured Data Publishing Gateway） | 适合行列结构的数据：API/网关状态、配额、资源清单、日志、统计 |

禁止项：
- **GitHub 上原则上不直接改**；改也要回到本地工作树再发布。
- **不要把 Handbook 正文 / 设计文档 / 长期知识 / 记忆正文复制进飞书**。

## 2. 闭环：单向发布，不双向同步

- **知识管线**：本地 Obsidian → git → GitHub 镜像 → AI/Agent 阅读
- **数据管线**：运行系统 / 录入 → 飞书 Base → 单向 export → GitHub Pages JSON（Read Model，禁止反向写）→ AI/Agent 读取

**坑A**：镜像与真源**双向同步原则上禁止**（单人系统不值得维护冲突解决机制）。

## 3. Owner Source 表（对象 → 唯一可写源）

| 对象 | 唯一可写源 |
|---|---|
| 项目文档 | 本地 Obsidian |
| Handbook | 本地 handbook 仓 |
| 项目台账 projects.yaml | 本地项目仓 |
| 个人记忆 | D:\记忆 |
| GitHub 镜像 | 派生（只读） |
| GitHub Pages JSON | 派生（只读） |
| 飞书原生运营表 | 飞书 |
| Agent 运行状态 | Agent memory 系统 |

## 4. Obsidian vault：压到 2 个

- **Vault A = Work**：Handbook + 项目索引 + 所有项目文档合一个 vault。**合并 vault ≠ 合并 git repo**——各项目仓保留各自 `.git`。
- **Vault B = Memory**：单独保留，不再压。理由=安全边界 + 生命周期边界（“这个系统是什么” vs “我最近在怎么理解/在干什么”不该混在同一搜索空间，避免 Agent 把临时判断/私人信息当正式事实）。
- **底线：2 个 vault 可以，1 个不推荐。**

**坑B**：Work vault 根目录**不要**做成一个大 git 仓（会陷入 nested repo / submodule / ignore 死循环）。
- **⚠️ 现状例外（2026-10-08 郭老师裁定：维持现状）**：`D:\Work` 根目录**事实上已存在一个大 git 仓**（无 remote，只当"vault 结构快照"用，不发布）。他选择保留而非拆解，理由是拆解要先逐项目确认"有没有只在根仓被跟踪的文件"，风险大于收益。**配套约束**：① 子项目仓自治，根仓只记结构变动；② 嵌套仓目录必须在 `.gitignore` 里列出（现为 `/AI平台/`、`/逆天主题/`、`/通用规范/`、`/元智能/`、`/项目索引/`、`/跃己/`、`/课程思政教学竞赛/`、`/AI精听训练器/05_发布与问诊/listenloop-{project,curated}/`），否则 `git add` 会把嵌套仓变成 gitlink（只记指针、丢内容）；③ 根仓**永不 push**，发布一律走各项目自己的仓。

## 6. 两个 memory 项目定死区别

- **yongtai-memory** = 人的记忆 / 调度大脑长期上下文；真源 D:\记忆，GitHub = 脱敏镜像。
- **ai-hub-memory** = Agent 系统运行 / 协作记忆（STATE / DECISIONS / CHANGELOG / coordination），**不是个人 PKM**。**不要为了“仓库少”强行合并**（数据类型不同）。

## 7. 发布与隐私红线（呼应 40-安全红线）

- **坑C**：不要把整个 `.obsidian` 公布。忽略 `.obsidian/workspace.json`、`workspace-mobile.json`、缓存、插件运行数据、含机器路径的配置。跨机同步只需 模板 + 必要插件配置 + CSS。
- **坑D**：D:\记忆 分 `private/` 与 `publish/`；GitHub 上是“公开允许集中的**忠实镜像**”，**不是**所有私人记忆字节的镜像。发布前按 40-安全红线跑密钥扫描。

## 8. 最终四要

1. 两个 Vault：Work / Memory，不再按项目开 vault。
2. Git repo 数量按版本边界决定（repo 数量 ≠ vault 数量）。
3. 三工具定位：Obsidian = 写知识；GitHub = 版本化 + 发布给 AI；飞书 = 管结构化动态数据。
4. 全系统唯一同步法则：一个对象只能有一个可写真源，其余只能是 mirror / projection / cache / audit log。
