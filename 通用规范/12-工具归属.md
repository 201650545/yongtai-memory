# 10 · 协作与工具归属（跨项目通用）

> 版本：**v1.2**（2026-10-08 郭老师裁定"补上归属真空"）
> **补这条的原因**：2026-10-09 排查夸克网盘备份时发现，`backup_quark.ps1`（备份 Work＋记忆＋12 个 A 档资料，管的是全系统）寄生在 `小红书点赞分析\scripts\` 下、计划任务还叫 `XHS_WorkBackup_Daily`——**跟小红书毫无关系**。代价是：① 排查花了两小时才找到；② 收尾自检扫不到它；③ 没人敢动别人的代码。根因＝**规范只覆盖了"项目内的东西"，没覆盖"跨项目的工具"**。

## 一、工具归属三问（判断一个脚本放哪）

1. **它只服务一个项目吗？** → 放那个项目的 `scripts\`，且只被那个项目的入口调用。
2. **它服务多个项目、或服务整个系统吗？** → 放 `D:\Work\工具\<用途>\`，**并在该目录下建 README**，写清三件事：**谁在跑（哪个计划任务）／跑什么（一句��）／坏了会怎样（影响面＋怎么手动补跑）**。
3. **它属于某个机制组件吗？**（巡检、沉淀、契约探针属于元智能）→ 放该组件的 `runners\` 或 `scripts\`。

## 二、红线

- **跨项目工具禁止寄生在业务项目目录里。** 业务项目的 `scripts\` 只放本项目脚本。
- 发现"某项目里藏着管全系统的东西"＝**归属错位**，必须迁出，且在迁移记录里写清新旧路径。
- **计划任务命名跟归属对齐**：跨项目任务**不得带业务项目前缀**。备份叫 `Work_Backup_PackDaily`，不叫 `XHS_WorkBackup_Daily`——否则从任务名判断归属必然出错。
- **规则要能回答"新东西放哪"**：新增跨项目脚本时，若本文件答不上来，说明这条规矩有缺口，应就地补，而不是随便找个目录塞进去。

## 三、跨项目工具的登记要求

放在 `D:\Work\工具\` 下的每个工具目录，README 至少含：

| 字段 | 说明 |
|---|---|
| 入口命令 | 完整可复制的命令行 |
| 计划任务 | 任务名＋触发时间 |
| 依赖 | 外部 CLI / 凭据位置（**不写明文凭据**，只写存放位置） |
| 回执 | 怎么判断成功（**没有回执＝失败**，不许静默） |
| 手动补跑 | 出问题后他/我该怎么立刻补一次 |
