# 记忆条目字段规范（`kind` / `status` / `scope` / `requires`）

> **来源**：2026-10-21 郭老师定；依据论文 arXiv **2610.26825**（MemT-1.0）**附录 G 的四个案例**。
> **配套**：`C:\Users\郭永涛\AGENTS.md` **第 20 条**（机制单写源）｜迁移脚本 `D:\Work\元智能\10_AI自成长引擎\scripts\backfill_memory_fields.py`（幂等可重跑）

## 一、为什么有这四个字段（论文依据）

| 论文案例（一手） | 论文证明了什么 | 对应字段 |
| :-- | :-- | :-- |
| G.2 问"对话从未提过的生日" ⇒ 答 **"I don't know."** | **"不知道"必须是一等答案** | `status: unknown` |
| G.3 蓝徽章→可订房；**可订房＋已登记→可领工具箱** | 缺一前提就不能推 | `kind: rule` ＋ `requires` |
| G.4 原定周六→正式改周日；**有人提议改周一但没定** | **"已定"与"在议"必须分开** | `kind: fact` vs `kind: proposal` |
| G.1 答对 ＋ **属性不串味**（红工具箱不跑到陈伟名下） | 记忆必须带归属边界 | `scope` |

## 二、字段定义

### `kind`（这条是什么）
| 值 | 含义 | 判定口径 |
| :-- | :-- | :-- |
| `fact` | **可复现的事实**：能独立回答它声称回答的问题 | 默认值；文件里没有"规则/待定"语义时 |
| `rule` | **有前提的规则**：满足 `requires` 才成立 | 教训类、流程类、通用规范类 |
| `proposal` | **未定／在议**：还没拍板 | 文件里出现 `captured`／"待他定"／"未展开"／"在议" |
| `reference` | **资料与规范**：指向别处，不自带结论 | 参考类、调研归档类 |

### `status`（这条现在还成立吗）
| 值 | 含义 | 判定口径 |
| :-- | :-- | :-- |
| `active` | 生效中 | 默认值 |
| `archived` | **封存**：不再被引用，但**保留可溯源**（≠ 被取代） | 位于 `归档` / `废弃存档` 目录，或条目自身写明"已封存" |
| `superseded` | **已被取代**（**必须同时写 `superseded_by` 指向取代者**） | 结论被推翻／资产被撤销／规则被新版本替换 |
| `unknown` | **证据不足**——这就是"我不知道" | 结论无法核实、需要人工确认、来源不可达 |

> ⚠️ `superseded` **不允许没有 `superseded_by`**；`unknown` **不允许被当成默认值用**。
> 这两条是 MemT 论文 G.2/G.4 的直接落地。
> ⚠️ `archived` 与 `superseded` **不要混用**：封存＝"它还在，但别再引用了"；
> 被取代＝"它错了/没了，请看那条新的"。

### `scope`（这条归属于谁）
归属标签（项目／系统／渠道），**防串味**用。多项目、多渠道、多账号并存时，
检索与引用**必须带归属**。⚠️ 归属**不确定就不要写**（空比错好）。

### `requires`（规则型条目的前提清单）
只对 `kind: rule` 有意义：列出该规则成立所**必须同时满足**的前提。
**引用规则型记忆时，必须逐条验前提是否成立**（论文 G.3：缺"已登记"就不能推"可领工具箱"）。

## 三、三条硬规矩

1. **证据不足就写 `unknown`／"未判定"**，不许填默认值、不许猜。
   （反面教材 2026-10-21：型号匹配把 DeepSeek V4.1-Flash 误判成"已接入 qwenwork/flash"——就是"不确定却给了确定答案"。）
2. **资产被撤销／结论被推翻 ⇒ 必须标 `superseded` 并指向取代者**。
   （反面教材同日：能力总账说 `search_mcp_server.py` "✅ 已改进程内直连"，而该文件已随引擎池删除 ⇒ 事实一直"活着"。）
3. **"已定"与"在议"分开**（`kind: proposal` 即"在议"）。
   （正面样板：想法池的 `captured / assigned / done` 状态机＝论文 G.4 的同构实现，方向已被验证。）

## 四、写法示例

```yaml
---
name: rule_示例_引用规则前必须验前提
description: …
type: rule
kind: rule
status: active
scope: 记忆仓
requires:
  - 前提一：来源是一手或已标注二手
  - 前提二：证据可核实
updated: 2026-10-21
---
```

```yaml
---
name: project_示例_还没拍板的事
type: project
kind: proposal
status: active
updated: 2026-10-21
---
```
