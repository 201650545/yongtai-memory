## Agent 读取顺序

每次对话开始时，Agent 按以下顺序读取本地文件：

1. `长期记忆.md`（用户画像与稳定约束）
2. `中期记忆.md`（当前项目规则与决策）
3. `短期记忆.md`（上次会话的上下文与待办）

## 单写真源规则

同一记忆对象**只有一个可写真源 = 本目录 `D:\记忆`**；其余是派生（read-only）：

| 位置 | 角色 | 来源 |
|---|---|---|
| `D:\记忆` 本地 .md | **唯一 canonical（可写）** | 编辑地 |
| GitHub yongtai-memory | AI 可读镜像（只读） | git publish |
| 飞书记忆编辑记录 | 审计投影（append-only） | 可选记录 |

发布方向固定单向：编辑 `D:\记忆` → commit → push → 镜像。反写仅限恢复用，不构成双轨。

## 各文件更新规则

### 长期记忆.md
- 更新频率：低
- 触发：用户明确表达新偏好/约束/技术栈，或总结出新教训
- 操作：在对应章节追加，旧内容一般保留

### 中期记忆.md
- 更新频率：项目周期内
- 触发：新项目规则、决策记录、工作流程变更
- 操作：项目结束后，内容归档到 git 历史，本地清空对应章节

### 短期记忆.md
- 更新频率：每次对话覆盖
- 触发：每次对话结束前
- 操作：
  - 上次未完成待办 → 保留并标记「延续」
  - 已完成待办 → 移除或标记「已完成」
  - 新任务上下文 → 覆盖写入

## 标题标记规则

记录变更时，使用以下前缀：
- `[新增]` — 新增的记忆条目
- `[更新]` — 修改了已有条目
- `[完成]` — 已完成的待办或任务
- `[归档]` — 从中期/短期移入飞书归档

## 变更日志格式

每条变更日志格式：
```
YYYY-MM-DD [类型] 简短描述
```

示例：
```
- 2026-06-30 [新增] 飞书记忆多维表格建立完成
- 2026-06-30 [更新] 新增硬性约束：不修改路由文件
- 2026-06-30 [完成] 记忆系统本地文件初始化
```
