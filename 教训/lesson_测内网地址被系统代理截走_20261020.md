# 教训：内网地址被系统代理截走 ⇒ 502 假象（差点改坏生产配置）

## 一、症状

测 `tailscale serve` 的入口，全部 502：

```
HTTP/1.1 502 Bad Gateway
Connection: keep-alive
Proxy-Connection: keep-alive
Content-Length: 0
```

后端本地却是好的：`127.0.0.1:8787/health` = 200、`127.0.0.1:3100/` = 200。

## 二、真因（本机）

- **系统代理开着**：WinINET `ProxyEnable=1`，`ProxyServer=127.0.0.1:7890`（Clash）
- **环境变量也设着**：`HTTP_PROXY` / `HTTPS_PROXY=http://127.0.0.1:7890`
- **`NO_PROXY` 里没有尾网地址**：只有 `localhost,127.0.0.1,::1,.local`
  ⇒ **所有访问 `*.ts.net` / `100.100.73.85` 的请求都被 Clash 截走**，Clash 回 502。

**证据（决定性对照）**：
```
走代理   → 502
不走代理 → 200 / 288828B / 27ms
```
并且 20:20 另一位 Agent 记的「实测 HTTP 200 / 288KB / 31ms」与"不走代理"的结果**完全吻合** ⇒ **那条记录本来是对的，是我误判成假绿**。

## 三、我犯的错（这一段才是重点）

我因为 502 就一路深挖，做了这些**本不该做的动作**：

1. 判「serve 回源必失败」⇒ 试了 loopback / 局域网 / tailnet IP 三种后端 ⇒ 全 502 ⇒ 又判「这个节点上 serve 整体失效」
2. 判「节点缺 HTTPS 能力（`CapMap https=null`）」⇒ 判「HTTPS 两条必死」
3. **`tailscale serve reset`**（动了他的配置）⇒ 靠备份才恢复
4. 起了个多余的转发器进程 + 脚本（已停用并可恢复删除）
5. 在交接单/广播里**写下了错误结论** ⇒ 会把下个 Agent 引去改 ai-hub 与 nssm 的生产绑定

**根子**：把"我这边测不出来"直接当成了"东西坏了"，没先问一句"**是谁回的 502**"。

## 四、正解（可复用）

1. **先分清 502 是谁吐的**：
   - 响应头有 **`Proxy-Connection`** ⇒ **中间有代理**，不是后端；
   - 响应头有 `server: uvicorn` / `server: nginx` 等 ⇒ 才是后端。
2. **对照测试**：同一条 URL，**加 `--noproxy '*'` 再打一次**。两次结果不同 ⇒ 立刻怀疑代理。
3. **测内网/尾网地址一律绕过代理**：`curl --noproxy '*' …`；脚本用 `requests` 时传 `proxies={}` 或 `trust_env=False`。
4. **改机器的代理绕过列表**（本机已修）：
   - WinINET `ProxyOverride` 加 `100.*` 与 `*.ts.net`（`100.*` 覆盖 Tailscale 的 CGNAT 段 `100.64.0.0/10`）
   - 用户环境变量 `NO_PROXY` / `no_proxy` = `localhost,127.0.0.1,::1,.local,100.*,*.ts.net`（**只对新进程生效**）
5. **改配置前先问一句"这个结论有多硬"**：若结论会导向"改生产配置/删服务"，先把对照实验做完再动。

## 五、附带收获

- 顺带确认了 Tailscale 端到端**真的通**（手机经 adb 无线调试实测：`:8080/health` 200、手机浏览器成功打开电脑的 :3100 控制台 HTTPS 仪表盘）。
