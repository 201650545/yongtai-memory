# 热更新要求的真实完成度

**结论**：逐条核对 22 条热更新要求，真实完成度是 **已做 1 / 部分 12 / 没做 9**。
核心缺口 = **App 内没有内容源抽象**（`ContentRepository` 检索 **0 命中**），
所以所谓「热更」实为「**热推 ＋ 重启 App**」；而**主题令牌是编译期常量** ⇒
**改主题必须重打 APK**，没有任何绕路。

**判据**：

- 宣称「本项支持热更新」必须能指出 **App 内的内容源抽象** 与 **运行时替换入口**；
  找不到 ⇒ 一律按「热推 + 重启」计，不按热更新计。
- 改主题令牌 / 色板 / 字体档 ⇒ 按「**要重打 APK**」计工时与排期。
- 汇报热更新进度时用「已做 / 部分 / 没做」三档，**不许把「部分」说成「已做」**。
