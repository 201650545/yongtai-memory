# AIHOT 席级补位雷达

> 2026-10-21 郭老师起意：「它这个开源，其实不仅可以局限于 AI 资讯源，是不是还可以跟现有项目创新融合」
> ⇒ 定的融合对象：**`:3100` 编排器的供给侧信号**（不是内容侧选题，见下）。

## 一、融合对象与理由

- **AIHOT（时间面）**：什么时候热议、发布了什么新模型 —— 唯一活的增量源
- **AA 快照（能力面）**：值不值得接
- **`:8787`（供给面）**：接了没有、有没有账号池供得上
- **`:3100`（席面）**：**不是模型清单，是 10 个「席」**：`flash` / `high` /
  `voice-asr` / `voice-tts` / `voice-clone` / `voice-caption` / `voice-translate` /
  `voice-chat` / `voice-realtime` / `image-gen`；每席背后是候选池 ＋ 编排器
  （`auto_orchestrate.py`，按能力带/AA/实测速度/**免费性前提**选当班，`paid-*` 被显式排除）
- ⇒ **缺的正是「对账」那一步**：编排器只看存量，外面出了什么新货它不知道。
- **内容侧（小红书/英文工厂/句读）判为弱、不接**：AI 圈热点偏 B 端，且那几条线的选题现在是人给的。

## 二、方案与排期（★ 已被两轮外部评审收窄）

| 期 | 做什么 | 碰编排器/路由？ |
| :-- | :-- | :-- |
| **一期** | **只做①层**：每天一份可审计的「新型号候选清单」（8 字段） | 都不碰 |
| 二期 | ②席位映射（人工审核表为主）＋ ③网关对账与免费性闸门 | 都不碰 |
| 三期 | ④完整席级表 ＋ 建议动作（生成实测命令，不执行） | 都不碰 |
| 四期 | 才谈纳入编排器候选池 | 碰，且必须人工点头 |

**一期成功指标 =「每条建议都能解释为什么」，不是「每天发现多少新品」。**

## 三、两轮外部评审（GPT-6 Sol · Chat 镜像站 · 2026-10-21）的实质结论

材料与回复（公开仓 `201650545/workspace-index` 的 `reviews/`；回复原文在
`D:\Work\元智能\10_AI自成长引擎\docs\方案\20261021_gpt6_席级补位雷达_评审回复*.md`）：

1. **它抓到了我一个真 bug（已修）**：型号匹配用「网关 tail ⊂ 候选型号」，
   于是 `qwenwork/flash`（tail=`flash`）把 `DeepSeek-V4.1-Flash-20261017` 与
   `MiniMax M3.1 Flash` **双双误判成已接入**；且网关清单存成 `set` ⇒ **每次跑命中不同 id**。
   修法：短 tail（<6 或无数字）失去匹配资格 ＋ 遍历排序 ＋ 新增「家族级」中间态。
2. **①层状态改名**：`已接入` → **目录型号级命中 / 目录家族级命中 / 未发现目录匹配**。
   **「目录存在」≠「API 可调用」≠「免费」**——后两者是③层的责任。
3. **免费性闸门 = 7 步失败关闭**：`DATA_UNKNOWN → PAID_EXCLUDED → ROUTE_UNRESOLVED →
   ACCOUNT_UNAVAILABLE/UNKNOWN → QUOTA_UNKNOWN/UNAVAILABLE → FREE_UNVERIFIED → FREE_ROUTE_UNSAFE`
   ⇒ `FREE_PATH_VERIFIED`。**`paid-*` 只是负向过滤器，免费资格必须有正向证据**
   （需新建「经审核的免费线资格记录」）。
4. **四个 `unsupported` 渠道的裁决**：raccoon / loomy / qoder **不允许自动入免费线**
   （缺账号可用性、额度语义、明确无费用政策、实际路由关系）；workbuddy-intl **连独立账号都没有，更不行**。
   ⇒ **不能把「网关不支持额度查询」解释成「免费且无限额」**。
5. **实体类型与事件类型必须是两个独立维度**，各给了一张带把握程度的规则表；
   规则判不了就留 `unknown`（比强行分类有价值）；`category=ai-models` 只作弱先验。
6. **链接证据一期不做通用抓取**：只保留链接 + 只对已确认的官方发布信源做轻量路径解析。
7. **①层 8 字段**（原始条目/规范候选型号/实体类型/事件类型/来源证据/匹配等级与理由/重复归并关系/人工核验状态）。
8. **初始别名表工时**：精简可用 **2–4 人天**；全量严格 3–6 人天+。省法：先归并、优先审近两周、
   **不只审"未接入"**、优先审有补位价值的事件、审核结果复用。
9. **它纠正了我加的两条验收标准**：
   ①「tail 长度≥6 且含数字」只是**必要过滤条件，不是匹配正确的证明**（语义一致性必须人工核）；
   ②「没改路由」**不能**靠当前路由表证明，要**运行前后快照或变更审计**。
10. **它写进方案的三条硬规则**：①层型号/版本/变体/事件分开判，日期别名只在核验上下文生效；
    ③层免费性需正向证据、`unknown`/`unsupported` 必须阻断；④层自动检查通过≠事实已验证。
