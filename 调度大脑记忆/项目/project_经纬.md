# 经纬 · 无限画布 + 多模型 DAG 编排插件

> **本条目只补记忆侧的状态与裁定，正文不复制**。项目真源：`D:\Work\经纬\docs\00-项目总览.md`。

## 一句话

用户对**唯一的主 AI** 说话，主 AI 生成一张可执行的 DAG 画布，并行调度多模型与 Claude Code 节点，产物落在节点上并可局部重跑。
**画布是观察与干预界面，不是执行真相**（图 JSON + 运行记录 + 产物文件才是）。

## 它替代的旧流程

现状是线性串行 `选题 → 产品 → 文案 → 校对 → 发布`，四个瓶颈：不必要的串行等待、人工逐段催、结果流转没有契约与版本、不可观察也不可局部回退。

## 三条原则（钉死）

1. **图是唯一事实源**（聊天上下文不算）
2. **单点调度**（只有调度器能启动节点）
3. **视图只读**（画布不能直接改运行状态）

## 现状（2026-10-19）

## 三份调研方案的取舍（重要判断）

三份是"同一需求、三个模型各答一遍"，可信度差别很大：

> **判可行性用 C（claude），画图纸用 A（chatgpt），做交互用 B（gemini），接口一个都别信。**

（接口必须自己跑 `06-接口核实.md` 验证）

## 边界（第一版不做）

不做新聊天系统（DSH 已有）／不做通用拖拽编辑器（那是 Dify/ComfyUI）／不做未授权自动发布与反自动化规避／不做多用户计费 SaaS／**不让 Claude Code 当总控**（只做代码类节点）。
