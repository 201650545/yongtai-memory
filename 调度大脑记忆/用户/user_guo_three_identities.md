# 他是谁：三身份 + 四个贴墙原则

**一句话（他自己写的）**：「我不只是"敲代码的"，我是"判断方向 + 做出东西 + 持续验证它有没有生命力"的产品型开发者与管理者。」

## 三身份，永不拆开

| 身份 | 负责 | 他自己点出的最易犯错 |
|---|---|---|
| 开发者 | 把想法变成能跑的东西 | 陷进技术细节，忘了"这东西要有人用" |
| 管理者 | 定目标、排优先级、控风险、验收 | 只管理"任务量"，没管理"方向对不对" |
| 学习者 | 从每轮做成/做砸里提炼方法 | 重复踩坑，不沉淀成规则 |

做东西时是开发者，做选择时是管理者，做完后是学习者。

## 四个贴墙原则（他标了"不改"）

1. **管理风险，不管理任务**——风险 = "做了一年发现没人需要"，不是"这周没做够 N 小时"
2. **先证明有人愿循环，再扩建世界**——世界是放大器，不是发动机
3. **设计文档是假设列表，不是承诺书**——改动它不是失败，是学习
4. **限制野心，不限制想象**——想象可以飞很远，这周该做的就那么一条纵线

## 公式（他要求自己背下来）

> 极小核心闭环 × 可观察 × 小步修改 × 可验证 × 可回滚 × 定期删东西

## 怎么跟他协作才不踩雷

- 他判定"做得对不对"的标准**不是产出量**，是「这条路径有没有真的被反复使用」
- 大方向（世界观/路线/映射）**先设计文档**；低确定性（手感/数值/UI 沉浸）**直接做原型别写长文档**。判断规则他自己给了：「如果这个错了，修改成本大不大？」大→先文档，小→先原型
- 他自评最常犯的病：**扩写设计文档替代做产品**、**大目标一股脑冲不拆小**（2026-09-29 再次自述）。所以给他东西要**每片能单独跑给他看**
- 新功能进 Parking Lot 前必须先答「它解决哪个已观察到的具体问题」，答不出就拦下
- 三区验收清单：产品价值／用户体验／技术，**三区全过才开发**
