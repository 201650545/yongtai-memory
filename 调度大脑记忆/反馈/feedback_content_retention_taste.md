# 他留不留一条内容，用的是这套轴

任何"帮我看这批东西哪些值得留"的活（点赞笔记、收藏、素材库、教程链接、甚至 skill 去重）都适用。**这套判据是他用改判一条条校准出来的，不是我推出来的**，所以改动要谨慎、被改判要留痕。

**唯一的判断轴＝长期有用性**。明确不要"备选观察／悬而未决"这一档：**要么留要么删**。给不出判决的条目说明自己没讲透，回去讲透再判。

**留（满足任一，且有实质内容）**：
1. 已落地实物（已装／已产出／他明确要动手）；
2. **不过时的认知与方法论**——脱离工具版本仍成立的判断力、可复用的提示词与工作流；
3. 可迁移的技术思路，且能接到他的主线（AI 内容创作／知识管理／小红书／Vibe Coding）；
4. **稀缺的"怎么办"型生活／社交程序知识**（座次敬酒买单、高难手术怎么选医生、领导出差 SOP）——这类很难系统学到，属保留；但**公开可查的显性政策信息不算**（他据此删过军队文职招考科普），鸡汤／情绪价值也不算。

**删（多为多条同时命中）**：会过时的情报（版本号、免费额度、优惠、限免）；要花钱订阅；要重折腾环境（WSL／OAuth／命令行部署）；纯产品软文与**四无**（无工具名、无步骤、无提示词、无链接，"评论区领取"类）；高风险（封号、实盘炒币理财）；他已自行完成或已放弃；**对他构成降级方案的**（他能直接写代码，就不留模板建站平台）；**他已有更强替代的**（已装官方 Remotion skill，就删 Remotion 教程）。

**一条元规则最容易做错：「笔记可删、案例可留」**。思路值得留但挂在具体版本上时，把不依赖版本的部分**提炼进长期案例文件**（编号续接、写明源笔记 ID、并**明确写"不留什么"**），原笔记照删。他就是这样把 3 个案例从删除堆里救出来的——所以"删"不等于丢内容，**别因为舍不得内容就不删载体**。

**同款要主动指认**：与历史判例同款的笔记要当场说"同款你此前已删过 N 篇"；同一工具/项目的重复笔记合并成一条（avatar-forge 两篇、PocketBay 三篇就是这么处理的）。

**Why**：他的库长期是"只增不删"，2026-09-28 才换轨为筛选制；换轨后累计真删 131 篇、精选只留 26 篇，说明他要的是**能被快速调用的少数资产**，不是规模。

**How to apply**：预判阶段**绝不改任何数据**；每条给"①一句话是什么 ②具体能干嘛 ③坑（花钱／环境／时效／风险）④明确预判＋判据编号"；建议是**可被推翻的**，被改判后把新规则回写进规范文件留痕。生图类批量任务先提示他自带的镜像版路径，不推荐第三方中转站。流程细节见 [[调度大脑记忆/流程/workflow_two_round_screening_and_true_delete]]。
