# 协作纪律与台账格式（跨项目通用）

## 角色分工（三条）

| 谁 | 干什么 |
|---|---|
| **人类** | 拍板方向、验收关键资产、批准对外动作（建仓库／推送／对外发消息） |
| **本地 Agent（Qoder）** | 任务编排、批量执行、验收落盘、文档与仓库维护 |
| **外部模型协作者（GPT 等）** | 凭公开仓库掌握项目全貌，自主设计产出，打包交付 |

⇒ **批量扫描、落盘、维护文档这类活属于本地 Qoder Agent 的职责范围**，不需要逐次请示；但**建仓库、推送、对外发消息必须人类批准**。

## 执行纪律（三条）

1. 设计 → 外部评审 → 人类拍板 → **逐次授权才动代码**
2. **编号方案获批后按数字顺序直接执行，不再反复确认顺序**
3. 新任务**先登记看板再做**；不虚报进度，失败如实列缺失清单

## 镜像站协作协议（vip-14 GPT，五条）

1. **Extended 红线**：每次发送前必须核实输入框旁按钮文字为 `Extended` 才允许点发送
2. **单系统单消息**：一条 Extended 消息只做一个系统级任务，携带该系统底图；禁止逐张连发刷屏
3. **交付形式**：zip 优先；Agent 侧从图片消息逐张提取落盘验收
4. **防虚报条款**：批量任务提示词必须包含「只有当每个文件名都对应一次真实成功的图片工具调用后，才允许说完成」
5. **验收落盘管线**：conversation JSON 提取 asset_pointer → 签名 URL → 本机中转 `POST /save/中文文件名` → 目检 → 改名入册

## 台账格式

**任务看板**：每任务登记 要求／验收标准／状态。状态**只有四种**：`待办 / 进行中 / 待验收 / 完成`。完成的任务**保留台账不删**。被阻塞的写明阻塞来源；**人类决策项单列，不阻塞其他轨道**。

**资产清单**：每项一行；状态**三态**：`✅ 目检合格 / ⏳ 生产中 / 📦 底图`。新资产先登记再使用。按系统分节，含 文件名／要点／状态。
