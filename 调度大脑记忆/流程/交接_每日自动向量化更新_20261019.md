# 交接 · 每日自动向量化更新

## 为什么做这件事

2026-10-19 实测：引擎 10-17 上线，**234 个会话里除执行者自己 44 次外，其他 Agent 只调用过 3 次**（且都是「试一下」性质，有一条还先 `Test-Path` 探文件在不在）。

功能本身是有效的——A/B 实测同一问题「怎么防止记忆被别的助手改坏」：

| 模式 | 返回 |
|---|---|
| 纯语义 | error_lessons / 双仓拆分 / 内容取舍（都不含「防止」「改坏」） |
| 纯关键词 | 索引 / 两审制真删 / 废弃逐字稿 |
| 混合 | 概念解释器 / 索引 / 两审制 |

三组结果完全不同 ⇒ 语义通道在按意思找，RRF 融合也在真工作。

但「做好了却没生效」有两处硬伤，本任务解决其中一处：

**向量覆盖率不完整 ⇒ 新内容在语义通道里是瞎的。**

实测：记忆库 1576 sections 只有 971 有向量（61.6%），向量文件停在 10-19 **01:32**，而索引是 **18:27** 重建的 ⇒ 当天下午所有新内容（经纬 / AIHOT 快照 / 索引改动）语义检索完全看不见。

## 技术要点（必读，别踩）

### 1. 直接跑 indexer.py 不会编码向量 ⚠️

```powershell
# ❌ 只建索引，不编码向量
python indexer.py "D:\记忆"

# ✅ 带 embedder 才会补向量
python -c "import sys;sys.path.insert(0,'.');import indexer;from embedder import Embedder;indexer.build_index(r'D:\记忆', embedder=Embedder())"
```

`indexer.py` 的 `__main__` 只调 `build_index(target)`，**没传 embedder**。
所以定时任务若只跑 `indexer.py`，向量永远补不上——这是本任务的核心坑。

### 2. 编码耗时实测

- 记忆库 620 个 section → **97 秒**
- Work 库缺 4047 个 → **约 10 分钟**（线性外推）
- 模型：`multilingual-e5-small` ONNX 118MB / 384 维 / CPU 单线程推理

### 3. 向量文件真实路径

`<vault>\.cache\knowledge.vectors.npy`

注意是 `knowledge.vectors.npy` **不是** `.vectors.npy`——
`Path(db_path).with_suffix('.vectors.npy')` 会把 `.db` 替换掉。

### 4. 增量能力已存在

`indexer._embed_missing()` 会对比 `vec_map` 与 `sections` 两张表，只编码缺失的，
每约 160 个持久化一次，**可断点续跑**。

## 建议方案

新建 `embed_backfill.py`（或给 indexer 加 `--embed` 开关），逻辑：

1. 遍历两个 vault
2. `build_index(vault, embedder=Embedder())` —— 一次完成增量索引 + 补向量
3. 日志记录：补了多少、耗时、覆盖率
4. 覆盖率 < 95% 时告警（写同一份 `渠道警报.log`）

## 已知坑

1. **gitignore 不支持行尾注释** —— 今日踩过，`/path/  # 说明` 会让规则静默失效，说明必须单独成行。
2. **`--vault` 参数**：`indexer.py` 已同时支持 `--vault X` 与位置参数 `X`，
   且目标目录不存在会报错退出（今日修复，防止误建 `--vault\` 垃圾目录）。
3. **Work 库很大**：37409 sections，全量建索引约 40 秒，补向量约 10 分钟，别在高峰期跑。
4. **编码占 CPU**：e5-small 单线程推理，跑时机器会热。
5. **别用 `git add -A`**（2026-10-15 郭老师禁），只 add 具体文件。
