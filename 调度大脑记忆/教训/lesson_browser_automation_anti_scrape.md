# 浏览器自动化：六条用真金白银换来的判据

现场是 `D:\Work\小红书点赞分析`（kimi-webbridge 驱动他已登录的真实 Chrome）。这几条**不限于小红书**，是所有"驱动真人浏览器做批量抓取／批量提问"的通用坑，未来做浏览器能力抽象与 computer use 时直接引用。

1. **别逐条进详情页**。连续访问 3~5 条详情页就会撞 404 或滑块验证码，整条链路被彻底阻断；而列表页卡片 DOM 已含封面/标题/作者/类型/点赞数。**单次 evaluate 拿全量 ＞ 多次导航**——慢是次要的，触发风控才是致命的。
2. **安全令牌要保留在链接里**。该带的授权参数（这里是 `xsec_token`＋`xsec_source`）一旦在清洗 URL 时被丢掉，下游 AI 直接返回 `NOT_FOUND`，而错误信息不会告诉你是缺参数。**凡是"复制出来的链接打不开"，先怀疑丢了授权参数，而不是怀疑 ID 错了**。
3. **主键要从路径末端匹配**。点赞页链接里 uid 和 note_id 都是同格式 24 位 hex，用宽松的"取第一个 24-hex"会**静默取成 uid**——不报错，只是数据全错。判据：ID 类提取一律锚定"路径末端＋紧跟 ? 或行尾"，并显式跳过已知 uid。
4. **受控组件不吃 `.value=`**。React/Vue 输入框只改 DOM 属性不会更新内部 state，发出去是空内容。必须走原型链原生 setter ＋ 显式派发冒泡 `InputEvent`；粘贴类交互（要触发站方的卡片识别）还得用 CDP **物理按键** Ctrl+V，`fill`/`execCommand` 都不算。
5. **流式输出没有"完成"事件**。打字机场景下 DOM 节点在连接建立第一时间就挂载入树，只监听"元素出现/数量 +1"会抓到半截。判据＝**过滤占位词 ＋ 长度过阈 ＋ 连续两轮内容完全一致**（平稳态窗口，2 秒轮询）。
6. **权限态失败先定性，别重试**。登录态过期、扩展未连接这类失败长得很像网络抖动：`502 Bad Gateway` ＋ `extension_connected:false` 的真实原因是**扩展只认官方 Web Store ID**，开发者模式加载的解压版永远识别不了。判据：**先看链路状态再看代码**；确认是身份/登录问题就交还人工重登，脚本绕过是纯消耗。

**还有一条关于提示词的**：输入框有**静默硬字数上限**（实测约 836 字拦、588 字过）——超长不报错、不发送。把链接改走"附件卡片"通道可以绕开字数占用。**凡是"发出去没反应"，先量字数。**
