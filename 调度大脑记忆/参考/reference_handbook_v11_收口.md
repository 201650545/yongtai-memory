# handbook v1.1 收口实录（2026-10-08）

## 起因

他问"Work 仓库里哪些项目用不着了"。盘点发现 `通用规范`（handbook）**最后 commit 2026-09-04、停更 34 天**，却被 12 处引用（客户端凭据网关×3、跃己×1、逆天主题×4、元智能×2、模板×1）。他指示先看这个。

## 挖出的 6 项"停更期间漏记"

1. **P0–P3 运行时微内核路由**（`C:\Users\郭永涛\AGENTS.md`，09-30 定稿）**handbook 里一个字没有** ⇒ 9 个项目声明"继承 v1.0"，真规矩却在别处，**两处分叉**。
2. **想法池 P0.6**（10-02 建，唯一共享登记册）同样缺席。
3. `50-…三工具规范` §5 写"yongtai-memory README 双轨矛盾待改"——**早已解决**，待办没划掉。
4. §7 坑D 的 `private/publish` 分目录仍未落地（它自己在版本注里写"下一条建议"）。
5. **他当天亲口的新铁律**："我之前所有规定，都以我最后一次跟你说的为准"——跨项目最高裁决规则，无处记录。
6. `40-安全红线` 只有 5 条，**缺"引用即校验"**；审计三起悬空指针/过期数字都源于此。

## 产出（commit `6b361b0` → `199f089`，已 push）

- 新增 `70-机制优先级与现行裁决.md`：① **郭老师最后一次明确指令 > 一切**；② P0–P3 只放指针（正文单写）；③ 冲突三动作＝先查时间戳／不脑补／改完留痕。
- 新增 `80-引用校验与证据纪律.md`：路径 `Test-Path`／数值跨真源比对／计数现跑；✅亲手核 vs ⭕未核标法；数字必须标口径（压缩 vs 解压）。
- `50` §5 划掉已解决项并标出**仍待办**：`D:\记忆\README.md` 顶部飞书字段段与"飞书退出主链"铁律有出入。
- README 版本 → v1.1，优先级链补上他那条最高指令。
- 12 处引用方 `handbook v1.0` → `v1.1` 全部同步（逆天主题、handbook 模板已 push；**元智能与跃己无 remote，只本地 commit**）。

## 两条可复用的判断

- **SSOT 停更的优先级高于单项目停更**。9 个项目都在引用一份 34 天没动的规范，这是系统性风险，不是洁癖问题。
- **停更期间的机制升级会形成"两处口径分叉"**：真规矩写在新文件、老引用方不更新，Agent 读到哪个纯属运气。发现这类分叉，正确做法是**指针化 + 升版 + 全量同步引用方**，不是各自补文档。
